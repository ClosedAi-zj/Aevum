# 真实样本（CC0）

**中文** · [English](README.en.md)

合成靶只能证明「实现和靶子的假设一致」，证明不了「实现和真实文件一致」——靶子和实现
由同一个人按同一份（可能记错的）理解写成，错在同一个地方时两边一起错，测试永远是绿的。
2026-11-01 就是这样发现 CFA 图案的取值映射整体偏移了一位：所有合规的 DNG 都被拒绝，
只有按错误约定写的合成靶能过。

这个目录放**真实相机/手机产出的文件**，用来跑一遍完整链路。

## 许可

全部为 **CC0 / 公有领域**。文件可随仓库分发，也可用于任何用途，无署名义务。
入库仍保留来源与校验值，是为了**可追溯**——换一台机器、几年后回来看，也能确认拿到
的是同一个字节序列。

### 这个文件为什么值得留

它同时踩中四个「只有真实文件才有」的坑，每个都让内置解析器在修之前直接失败：

1. **三通道 LinearRaw**：IFD0 是 852×640 的 YCbCr 预览，不是传感器数据；
2. **主图在 SubIFDs**：真正的 4032×3024 CFA 在子 IFD 里，只读 IFD0 会拿到缩略图；
3. **lossless JPEG + 瓦片**（compression=7）：元数据读得出来，像素仍然解不了——
   这条留给「拒绝 + 回退」的路径，正好验证回退不是静默换预览；
4. **CFA 图案 `[0,1,1,2]`**：按规范 0=R/1=G/2=B 写的 RGGB，把映射写错一位就整张拒绝。

对应判据：`crates/aevum-core/tests/raw_real_sample.rs`（四条，逐条做过变异验证）。

## 新增样本的规矩

- 必须 **CC0 或等价的无条件许可**，且许可在文件本身或来源页上可核实；不接受
  「网上找的」「厂商样例」（后者通常只许用于评估其软件）。
- 优先挑**已知会踩坑**的文件：新机型、新压缩方式、非 RGGB 排列。一个顺利通过的
  样本提供的判据价值很低。
- 体积控制在 15 MB 内，单文件入库；更大的写进 `scripts/fetch-samples.sh` 走下载。
- 上表补一行，写清来源 URL 与 SHA256。
