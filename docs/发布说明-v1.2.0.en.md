# Aevum Studio 1.2.0 Release Notes

[中文](发布说明-v1.2.0.md) · **English**

Released: 2026-11-01
Previous version: `1.1.0`

---

## In one sentence

**HDR export writes real files now**: AVIF 10bit + PQ (SMPTE ST 2084) + BT.2020, reference white at
203 cd/m², anything above white climbing along the curve tail, with no homemade compression.

Along with it, three "slider moves, pixels don't" bugs are fixed. **Two of them change the rendering
of existing projects** — they were simply wrong: half of the `masking` range was dead, and
`contrast_linear` pivoted 0.235 (in encoded value) off mid-gray. Roll-back is in section four.

---

## Before you upgrade (three sentences)

1. **Install over the top**: unzip the new package over the old directory. No installer, no migration.
2. **Projects and settings stay put**: `<sequence>/.aevum/` and `%APPDATA%/aevum-studio` are read in
   place. This version only adds a `render.dynamic` field to projects, which older versions ignore.
3. **Two kinds of project will render differently**: those with masking between 25 and 100 (the RAW
   import default of 20 sits in that range), and those with both `contrast` and `contrast_linear`
   non-zero. To keep the old look, see the end of section four.

---

## 1. What changed

### HDR export: AVIF 10bit + PQ

In the previous version "HDR export (PQ / AVIF 10-bit)" was a reserved entry point with a `todo!()`
behind it. It now writes real files. Three decisions, each pinned by a criterion:

| Decision | Value | Why not the alternative |
|---|---|---|
| Reference white | **203 cd/m²** (BT.2408 HDR reference white) | Mapped to 100 nits, the same picture reads one stop darker than the SDR window next to it on an HDR display |
| Highlights | **No compression**, climbing along the curve tail all the way to PQ's 10000-nit ceiling | A soft knee means deciding for the user how much to crush, and it wipes out half of the "HDR tail" slider |
| Code range | **Full range** | Limited (16–235) eats both ends of PQ; measured round-trip max error 178/65535 for limited against 128/65535 for full |

Picking **HDR (PQ)** in the panel switches the colour space to Rec.2020 and the container to AVIF by
itself (the selections move — you can see it). Exporting any other combination is refused with a
reason and **never quietly falls back to SDR**: the interface would say HDR, the file would be SDR,
and it would look flat grey on an HDR display with no warning anywhere.

The encode path changed with it: no more temporary 8bit PNG relay; a 16bit RGB pipe feeds libaom-av1
directly, producing `yuv444p10le` at full range with nclx tagged `(9, 16, 9)`. The extra depth gives
the matrix maths and dithering somewhere to land — measured round-trip error is about half of feeding
10bit directly.

Reproduction check (`pq_codes_are_actually_written_into_the_file`): read the exported AVIF back;
`colr/nclx` must be `(9,16,9)` and the white patch code must land at **≈38059/65535** (PQ(203 nits) =
0.5807). Skip the PQ encode and the white patch is 65535 — twenty-seven thousand levels away, so it
cannot be mistaken. A correct tag over SDR pixels is precisely the hardest version of this bug to see.

### Fixed: half of the `masking` range was dead

The sharpening masking slider did **nothing at all** to flat areas between 0 and 50:

| masking | 0 | 10 | 25 | 50 | 75 | 100 |
|---|---|---|---|---|---|---|
| Noise gain before | 1.944 | 1.944 | 1.944 | 1.944 | 1.174 | 1.077 |
| Noise gain after | 1.944 | 1.944 | 1.816 | 1.385 | 1.174 | 1.077 |

Four settings, one number before the fix — identical to no masking. The threshold was a squared term,
which flattened the low end; a square root makes it respond from 25 on. Both ends are unchanged, so
`masking=100` renders exactly as before.

### Fixed: contrast (linear) no longer darkens mid-gray on the side

`contrast_linear` means "compute the contrast increment in linear light", but its pivot sat at linear
0.5, which is encoded 0.735 (73% gray). Fully turned up, mid-gray 0.5049 was pushed down to 0.4487 —
14 levels (8-bit) gone for free. The pivot now sits on mid-gray: mid-gray does not move at any
strength, and shadows and highlights pull apart in opposite directions.

One uncomfortable conclusion that comes with it: **with the pivot fixed, this slider's visible effect
is down to about 1 level** (max 0.0041 measured, around encoded 0.18). Almost all of its former
"effect" came from the misplaced pivot, not from linear light. So do not expect much from pulling it —
its value is in computing contrast in linear light at all, not in how far it moves.

### Fixed: AVIF export never actually worked with a real ffmpeg

Stills are written to a `<name>.part` temporary file and renamed atomically; the extension is `part`,
so ffmpeg cannot infer the container and reports `Unable to choose an output format`. Both paths now
pass `-f avif` explicitly.

The bug has been there since AVIF shipped and went unnoticed because every AVIF test starts with
"skip when no ffmpeg is found" — neither this machine nor CI had one, so it stayed green all along.
That is known limitation 3, and it gets fixed next.

### Clean-up along the way

- Removed the `todo!()` in `spatial::OutputEncoding::HdrPq`. The branch it guarded does not exist:
  export order is "sharpen, then swap the transfer function", so sharpening always acts on sRGB
  encoded values. A panic sitting on the export path's main road is just a bomb.
- Switching the panel to video mode now pulls the dynamic range back to SDR: final renders are SDR
  only, and leaving a combination that errors on export has no point.

## 3. Known limitations

1. **HDR applies to stills + AVIF only.** Video (x264/x265) is still 8bit SDR, and 16bit HDR in
   TIFF/PNG is not done either — that needs a PQ curve inside the ICC profile, not a one-liner.
   Combinations that cannot hold it are refused rather than fallen back from.
2. **There is no HDR preview mapping.** The panel keeps showing the SDR preview; to see HDR you must
   export and look at it on an HDR display or in a player. This is the most visible gap in this
   version and the next thing to close.
3. **CI does not install ffmpeg, so 12 tests never execute there**: 7 in `export_video.rs`, 3 in
   `queue_export.rs`, 1 in `retime_export.rs`, 1 in `export_stills.rs` — all "return if no ffmpeg".
   The AVIF bug this release fixes hid behind exactly that for a whole cycle. **"Skip when the
   dependency is missing" is not a test; it returns the illusion of green.** The fix is either an
   explicit opt-in switch (red unless `AEVUM_ALLOW_NO_FFMPEG` is set) or installing ffmpeg in CI.
4. **Demosaicing defaults to `cell_average`**; directional is implemented but off by default. It can
   be switched in the diagnostics panel and resets on restart. The direction test only considers
   horizontal and vertical, so 45° edges and coloured boundaries fall back to colour-difference
   constancy and remain well below ideal.
5. **There are no real camera RAW samples on this machine**, so that demosaicing data all comes from
   synthetic targets; behaviour on real photographs remains unverified.
6. **AI denoise is experimental**: no numeric golden, no objective acceptance. Do not base delivery
   decisions on it.
7. **Performance has no CI assertion, only manual readings** (the 1.0.0 baseline is in that version's
   release notes). Numbers are not comparable across machines.
8. **The exe is not code-signed**, so Windows shows a SmartScreen prompt on first run ("More info →
   Run anyway"). Verify downloads against `SHA256SUMS`.
9. **Seven parameter families are still fitted guesses** (`dehaze` transmission floor / guided-filter
   eps / radius / amplitude, `lut` slope blending for x>1, `black_soft`/`white_soft` width, sharpen
   profile and radius mapping). They are guessed identically on both sides, and the golden proves
   Rust == Python, not that the coefficients are right.

## 4. Roll-back

- **Program**: install `1.1.0` again
  (`Aevum-Studio-v1.1.0-windows-x64.zip`, sha256
  `d11f110e77887818978253d3a70389389d9192aed05d867460694ce4347175e0`).
- **Projects and settings need no migration**: this version only adds `render.dynamic`, which the
  older version ignores. What you cannot get back is the rendering.
- **To keep the old look without downgrading**: set masking to 100 (the two ends agree there) and set
  `contrast_linear` to zero.
- **Commitment**: if a blocking defect shows up after 1.2.0, `1.2.1` fixes it. Tags are not withdrawn
  and published assets are not modified.
