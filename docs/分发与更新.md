# 分发与更新

**中文** · [English](分发与更新.en.md)

程序怎么发到用户手上、用户怎么升到下一版、这一路上有哪几道检查。一页纸，写完现状、
三条路、信任链、签名的成本，最后是明确还没做的部分。

## 1. 现状：一条路

`scripts/package.sh` 跑完，`dist/` 下只有两样东西：

```
dist/aevum/                                       绿色包解压出来的树
dist/Aevum-Studio-v1.8.0-windows-x64.zip          用户下载的就是它
dist/SHA256SUMS                                   <64 位十六进制>  <zip 文件名>
```

`SHA256SUMS` 只有一行，就是那个 zip。格式与 `sha256sum -c` 一致，用户拿到后自己就能验：

```bash
sha256sum -c SHA256SUMS
```

这条路的优点是不需要任何服务端：没有安装器、没有注册表、没有管理员权限。缺点同样明显
——用户得自己知道「有新版本了」，而且升级 = 手动解压覆盖。

## 2. 三条路，各管一段

| | 绿色包（zip） | 安装器（`scripts/install/aevum.iss`） | 内置更新器（`crates/aevum-core/src/update.rs`） |
|---|---|---|---|
| 解决什么 | 单机、免安装、可放 U 盘 | 开始菜单能找到、`/SILENT` 批量部署、卸载知道该删什么 | 用户不用自己去发布页看 |
| 谁需要 | 工作站、临时机器、审查用 | 机房、培训班、公司统一部署 | 长期使用的个人用户 |
| 需要管理员 | 否 | 默认是（可 `/CURRENTUSER`） | 否（装在用户目录时） |
| 状态 | **已在用** | 脚本已就绪，**未在真机出过包** | 核心逻辑已就绪，**UI 入口未接** |

三条路装出来的**是同一个程序**：同一个 `aevum.exe` 与同一个 `tools/ffmpeg.exe`。
安装器不写「只有安装版才有的功能」，更新器也不假设自己跑在安装版上（它只关心
「新 exe 从哪来、目标 exe 在哪」）。

内置更新器的形状值得单独说一句：它**没有引入任何 HTTP 客户端**。下载走系统自带的
`curl.exe`（Windows 10 1803+），找不到就退到 `powershell -NoProfile -Command
Invoke-WebRequest`，两条都没有时明确报「本机没有可用的下载通道」并给出手动下载地址——
不静默失败。这样离线构建、依赖审计都不用为一个「检查更新」多背一个 TLS 栈。

## 3. 信任链

一条更新请求要过五道，任何一道不过就停下：

1. **HTTPS**：`curl -fsSL` 与 `Invoke-WebRequest` 都走系统证书库；`-f` 让 404 变成非零
   退出码，否则一份 404 的 HTML 会被当成「下载成功」写进 exe。
2. **标签必须是三段版本号**：`v1.8` / `v1.8.0-beta` 一律不认。比较是**数值**比较
   （`1.10.0 > 1.9.0`），不是字符串比较——按字节比 `"1.10.0" < "1.9.0"`，用户会永远
   收不到 1.10 之后的更新。
3. **资产按后缀挑**：`windows-x64.zip`。挑不到就报「没有匹配当前平台的资产」，不猜。
4. **SHA256SUMS 比对**：清单里**没有这一行也算失败**。把「找不到」当成「不用校验」是
   这类代码最常见的漏洞。
5. **签名（尚未启用）**：见下一节。

要诚实说清第 4 道的边界：清单和 zip 来自**同一个地址**，所以它证明的是「传输没坏、
镜像没偷偷改」，**不能**证明「发布者没被冒名」。真正的身份保证只能靠代码签名——那是
唯一一条「你不需要信任下载地址，只需要信任证书」的链路。

## 4. 签名：成本与三个选项

`scripts/sign.ps1` 是接入点，**默认不阻断打包**：没有证书时打印一行说明并 `exit 0`，
产物照出；只有「配了证书但签失败」才返回非零。签名一律 SHA256 + RFC3161 时间戳——
没有时间戳，证书一过期，**所有已经发出去的旧版本**都会变成「签名已过期」，而二进制一个
字节没变。

| 选项 | 成本 | SmartScreen | 适用 |
|---|---|---|---|
| **不签** | 0 | 前几百次下载会被提示「未知发布者」，累积声誉后缓解 | 现在就属于这一档 |
| **自签**（自建根证书） | 0（自己生成） | 对公网用户**几乎无改善**；只有把根证书装进信任存储的机器才认 | 内网批量部署 |
| **Azure Trusted Signing** | 约 $9.99/月 | 需要可验证的组织身份；通过后提示消失 | 面向公众发布的正经选择 |

结论：**面向公众发布就要选第三条**，自签只解决内网。在拿到证书之前，先保证
`SHA256SUMS` 一定随发布一起上传（目前它只写到本地 `dist/`），并把发布页地址固定下来
——这两件事是免费的，也是签名之前唯一能做的。

## 5. 怎么跑

```bash
# 绿色包（含 zip 与 SHA256SUMS，最后会解压回验一遍）
scripts/package.sh

# 安装器（需 Inno Setup 6 的 iscc；版本号从 Cargo.toml 之外显式传，默认 1.8.0）
iscc /DMyAppVersion=1.8.0 scripts/install/aevum.iss
# → dist/installer/Aevum-Studio-1.8.0-setup.exe

# 签名（可选；没证书就跳过一次说明）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/sign.ps1 -Path dist/aevum
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/sign.ps1 -Path dist/installer
```

安装器的静默参数：`Aevum-Studio-1.8.0-setup.exe /SILENT /NORESTART`，彻底无界面用
`/VERYSILENT`。静默卸载时**一律保留** `%APPDATA%\aevum-studio`（没人能回答那个对话框，
而误删配置不可恢复）；交互卸载时会问一次。

## 6. 待办（这一轮没做完的）

- **UI 入口**：`update.rs` 的 `check_remote` / `download_verified` / `install_script` 都
  没有调用方。面板里缺「检查更新」菜单项、缺下载进度、缺「重启以完成更新」的提示。
- **真机联调**：`install_script` 生成的批处理只在判据里做过**文本**断言。真实场景
  （Program Files 的权限、杀软在 `move` 时持锁、更新器自己被占用）没有跑过一遍。
- **真实签名**：证书没买，`sign.ps1` 只在「跳过」分支上跑过。
- **发布侧**：`SHA256SUMS` 需要作为 release 资产真的上传（现在只写到 `dist/`）。
- **更新范围**：更新器只换 `aevum.exe`，不换 `tools/ffmpeg.exe`、`licenses/`、
  `third-party-src/`。ffmpeg 升级要走整包或安装器。
- **回滚**：替换脚本失败会还原 `*.old`，但成功后立刻删掉备份——没有「降级回上一版」
  的路径，只能重新下载旧包。
- **`.aevum` 后缀关联**：没有做，因为工程文件不是「一个带扩展名的文件」，而是每个序列
  目录里的 `<序列根>/.aevum/project.json`。`.aevum` 是目录名，Windows 没有「双击目录用
  某程序打开」的机制；要做关联得先有单文件工程格式。
