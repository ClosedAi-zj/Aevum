## 1. Research findings

### 1.1 Camera Raw (15-17) edit-panel organization (verified against Adobe docs)

- **Fixed section order**: Basic -> Curve -> Detail -> Color Mixer (HSL / Color / B&W
  modes) -> Color Grading -> Optics -> Geometry -> Effects -> Calibration. Each section
  is one collapsible header.
- **Three panel modes** (set by right-clicking a header): Single (opening one collapses
  the others; the default) / Responsive (opens and closes to fit the screen) / Multi.
  Ctrl+1..9 jumps straight to a section.
- **Slider interaction**: label left, value right and click-editable; bidirectional
  sliders (exposure, temperature) originate at the center tick; double-click the handle
  to reset one slider; Alt+click the header's Reset resets the whole section; a small
  dot marks a section with edits.
- **Every section has an "eye" toggle**: press-and-hold hides that section's adjustments
  for a quick before/after.
- **Presets and Snapshots do not occupy the edit panel**: they are separate panels on
  the left tool strip next to Edit / Crop / Heal; "Previous Conversion" (history) sits
  there too.
- **The histogram is pinned to the top of the panel**, with draggable tone regions for
  temperature/tint.

### 1.2 Lightroom Classic's functional split

All grading lives in one right-hand column of the Develop module; merge tools (HDR,
panorama) are actions under the Photo menu, not panels; snapshots/presets/History live
at the bottom of the left panel -- **the core insight: Adobe separates "grading one
photo's parameters" from "generating one image from many frames" into two worlds**.

## 2. Left column: presets/snapshots/history/copies leave the sidebar

**Goal**: the left column keeps only the 52px tool rail; the canvas regains a full
column of width; secondary tools stop occupying prime space.

1. **Delete the left "History" section** -- the dock's History tab already has full
   undo/redo plus the step list (`tabs.rs::history_tab`); the sidebar copy is a
   redundant view. Not a move -- a deduplication.
2. **Presets + Snapshots + Grade Copies -> floating window "Presets & Snapshots"**:
   - Reuses the `title_frame()` floating-window spec (the eight `ui_tokens.rs` guards
     keep applying);
   - Three sections: built-in presets / snapshots / grade copies (a copy is "one saved
     set of parameters + keyframes", the same species as a snapshot; ACR files it the
     same way);
   - Three entrances: a permanent `Glyph::Sliders` icon at the top of the tool rail
     (hover: "Presets & Snapshots (Ctrl+K)"), a Develop menu item, and Ctrl+K;
   - The snapshot "+" action moves to the window header; semantics unchanged.
3. **`state.show_left` becomes the "Presets & Snapshots window" toggle**; the old
   settings.json key maps onto it on read (existing snapshots are state data and stay
   -- only the entrance moves).
4. The menu toggle previously named "left preset panel" becomes "Presets & Snapshots".

## 3. ACR-grade Develop panel

**Section reorder** (old -> new; parameters, MCP and the project format change zero --
UI organization only):

| ACR order | New group (ours) | Merged from |
| --- | --- | --- |
| Basic | **Basic**: white balance (temperature/tint) -> tone (exposure/contrast/highlights/shadows/whites/blacks) -> preferences (texture/clarity/dehaze/vibrance/saturation), three sub-headings inside | basic + color |
| Curve | **Curve**: three mode chips under the header (parametric / point / levels), same shape as ACR's Curve | curve + parametric + levels |
| Color Mixer | **Color Mixer**: two mode chips (HSL / B&W); HSL carries hue/sat/luminance | hsl + mono |
| Color Grading | **Color Grading** (unchanged) | grade |
| Detail | **Detail**: sharpening -> noise reduction | detail (already so) |
| Optics | **Optics**: lens corrections -> profiles | lens + profiles |
| Effects | **Effects**: grain -> vignette | effects + grain |
| Look | **Look (.cube)** (our extra, last) | look |
| -- | **Masks** (ACR keeps Masking on the tool strip; ours stays a group but moves to the tail, next to the canvas tools) | masks |

**Interaction upgrades** (all ACR-convention):

1. **Single-panel mode**: the header right-click menu gains "Panel mode: Single / Multi",
   persisted in settings.json. Single = opening one collapses the others (ACR default);
   Multi = current behaviour. "Solo this group" stays.
2. **Center tick on bidirectional sliders**: a 1px vertical notch at the track midpoint
   for signed sliders (ACR's origin mark), drawn with theme tokens, no bare colors.
3. **Double-click the track to reset**: ACR's "double-click the handle resets" -- a
   double-click anywhere on the track returns to default (same value-change path as the
   inline reset, no duplicate history entries).
4. **Header styling**: small bold title + a double rule under the header (1px rule plus
   a 0.5px hairline 2px below -- ACR's section signature); changed-dot / reset / help
   positions unchanged.
5. **Eye bypass** (P1, if the cost is contained): a `Glyph::Eye` on the header; press
   and hold temporarily bypasses that group's parameters (per-group bypass in the
   render chain). If the render-chain change exceeds one round, this degrades to
   "Ctrl+click the header previews the bypass" and the trade-off is recorded in the
   ledger.
6. First-screen open/closed strategy stays in `GROUP_SPECS` (Basic/Detail/Masks open,
   the rest closed -- ACR's default also opens only Basic).

**The other five modules (Sequence/Deflicker/Frame/Render/Audio) are untouched** --
this round touches Develop (grading) and the left column only.

## 4. Separating grading from the photographic tools

**New module `Module::Merge`** ("合成" / MERGE), the seventh entry in the module row.

**Order correction (as implemented)**: appended to the **end** of `Module::ALL`
(index 6) rather than inserted after Develop. The index is an external contract --
`Ctrl+Alt+<digit>` and the `ui.module` command both address modules 0-5, and inserting
in the middle would shift "3 = Frame" for every user's muscle memory and every script.
The visual order in the menu row (Merge sits right of Develop) and the index order in
`ALL` are two different things; the former is explicit in the menu row.

- Five groups move in: HDR / Panorama / Star-Stack / Time-Blend / Focus-Stack
  (the `hdr_group/pano_group/stack_group/timeblend_group/focus_group` functions move
  wholesale from `adjust.rs`, zero logic changes);
- The Develop panel drops their header registrations (`GROUP_SPECS` rows re-keyed to
  `Module::Merge`);
- The "Grade Copies" group leaves Develop -> third section of the "Presets & Snapshots"
  floating window (§2.2);
- The Merge module opens with HDR and Time-Blend expanded (the two most used), the rest
  collapsed;
- MCP tools (`hdr_merge` etc.), the project format and shortcuts are untouched: modules
  are a UI-organization dimension only.

**Rationale**: all five are "frames in, one image out" file-level tools; while grading,
99% of sessions never touch them. Mixing them lengthens the Develop scroll (21 groups
today) and visually demotes the core action of grading a photo.

## 5. Character-overlap fixes (zero tolerance)

Both located by code review and confirmed against the screenshot:

1. **Filmstrip thumbnails**: stars paint at `bottom-14..-7` while the frame number's
   baseline sits at `bottom-1` (MICRO is ~10px tall, reaching `bottom-11`) -- the two
   bands overlap vertically in `bottom-11..-7`, **in every cell**. Fix: keep the number
   bottom-left; move the stars to **right-aligned** (starting at `cell.right()-3-5x8`),
   same baseline band but horizontally separated (a 92px cell fits a ~26px number plus
   40px of stars with room to spare); flags stay top-left.
2. **Status-bar squeeze**: the status bar is one row of many segments
   (notice/progress/name/resolution/frames/stars/status/sidecar); at narrow widths egui
   squeezes instead of clipping. Fix: a uniform 8px + separator dot between segments;
   the status segment gets an adaptive `min_width` with ellipsis; add a
   `ui_tokens`/self-test criterion for `status_bar` (render once at 320px width, assert
   no segment pair with negative gap).
3. **Whole-UI sweep**: `--selftest` already counts shapes; this round adds a
   "text-rect intersection assertion" for the filmstrip and status bar (every pair of
   painted text galley rects must not intersect), so this class of mistake is caught by
   a criterion instead of eyeballs.

### 7.2 Interaction upgrades: four landed, one deferred

1. **Single-open mode** (ACR's default): `state.panel_solo` (persisted in
   `settings.json` as `Option<bool>`, default = single-open); opening a group folds its
   siblings in the same module (reusing `solo_group`'s scope logic); the fourth item in
   the group header's context menu is a checkbox, making it clear this is a
   **preference**, not a one-off action.
2. **Mid-point tick on signed sliders**: already implemented here
   (`min < 0 < max` draws a 1 px mark); nothing changed this round beyond adding it to
   the gate's coverage.
3. **Double-click the rail to reset**: also already implemented
   (`t.double_clicked()` writes the default through the same value path and the same
   history entry as the inline reset dot).
4. **Group header styling**: title size +0.5 -> +1.0; the separator moved from "single
   line on top" to "double rule at the bottom edge" (1 px solid plus a 55 % hairline
   3 px above it) -- ACR's section signature, and it separates "a section starts here"
   from a table row divider.
5. **Eye bypass**: **deferred**. `aevum-core`'s grading chain has no per-group bypass at
   all; doing it means changing the render entry signature (a temporary bypass set
   beside `GradeParams`), wiring both preview and export, and adding a press-and-hold
   event state. That is a round of its own, so the §3.5 degradation clause applies and
   the item goes to `遗留台账.md`. Single-open mode, the header reset dot and
   double-click reset already cover the main "compare one group" path.

### 7.3 Two new gates (both mutation-verified)

| Gate | What it catches | Mutation check |
| --- | --- | --- |
| `ui_tokens::text_never_overlaps_in_any_module` | seven modules x two languages, one frame each; text rects on the same row must not intersect | reverting the delivery path to character-count truncation -> red (`Render y=374 「预设表…」x path, 50.2 px`); removing the canvas right-edge clamp -> red (`Merge y=94 「Adjust」x「Undo Ctrl+Z」, 32.9 px`) |
| `ui_tokens::explicit_develop_field_lists_cover_the_spec_table` | the five sections laid out from explicit lists must cover every spec in the table | dropping `Field::Saturation` from the Basic list -> red, naming `basic / Field::Saturation` |

All three rules inside the overlap gate were forced by false positives: a same-string
repeat offset by <=1.5 px is a drop shadow (the filmstrip number is black + white);
only the clipped-visible part counts; rows are grouped at 3 px and overlap tolerance is
1 px. Each module also runs three warm-up frames -- egui converges panel widths from
content, and the canvas edge is still moving for a few frames after a module switch,
a 16 ms transient no user sees.

### 7.4 A real defect the gate caught on its first run

Switching modules left the canvas sitting on the dock tabs. The cause is not our code:
`egui::Panel` shrinks the remainder using the width it remembers while its own rect
already honours `exact_size`, so after a module switch swaps the dock content the two
disagree for tens of frames (+1.6 px per frame, about 0.6 s to settle). Fix:
`canvas_panel` takes its right edge from "window right minus the right-hand panel
constants (strip 28 + dock 372)", min'd with the remainder egui reports -- the layout
constants are right there, and deriving from them beats depending on a third party's
internal state.

### 7.5 No data or format breakage

- `GradeParams`, the project file, MCP tools and the export chain: **not one field
  changed**;
- `settings.json` gains only `panel_solo` (`Option<bool>`, default single-open); older
  files load as before;
- Collapse keys are mapped (`state::legacy_group_key`): `color -> basic`,
  `parametric/levels -> curve`, `hsl/mono -> mixer`, `grain -> effects`,
  `lens/profiles -> optics`, `copies` dropped -- a user's folded-group preferences
  survive;
- The `ui.module` command now accepts module indices 0-6 (6 = Merge), error text
  updated with it.
