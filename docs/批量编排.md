# 跨序列批量编排（F6，v1.7.0）

**中文** · [English](批量编排.en.md)

## 为什么有这一页

一条序列一次调用能做完，但「一个目录下十几个延时」才是真实工作量。以前的答案是让
agent 自己循环：`aevum_open_sequence` → 改参数 → 导出，十几轮下来状态一乱就没人知道
跑到第几个了。现在一条调用就给回「几段成功、几段失败、每段为什么」。

两个工具：`aevum_sequences_scan`（只看不写）与 `aevum_batch_run`（扫 → 入队 → 跑）。

## 扫描规则

| 规则 | 为什么 |
|---|---|
| 根目录自己 + 往下 `depth` 层（默认 1，最大 4） | 序列通常是父目录的子目录；库根 / 年月分层用 `depth: 2` |
| 认成序列就不再往里钻 | 序列目录里是帧，再往下钻只会把缓存目录当候选 |
| `.` 开头的目录直接跳过 | 序列自己的 `.aevum/`（工程、测光账、缩略图缓存）不是素材 |
| `skipped` 只记「有图却读不出来」 | 空文件夹不是缺陷；「里面有图但有我们解不开的格式」才是要说的那句 |

判据只有一条：**`Sequence::open` 的结论就是结论**（`sequence.rs` 是唯一真源），扫描器
不另写一套后缀判断——否则「扫描说这是序列、打开又说不是」这种漂移迟早出现。

## 批量跑的语义

| 行为 | 缺省 | 为什么 |
|---|---|---|
| `confirm` | 必填 | 会批量写盘，与 `aevum_queue_run` 同一道闸 |
| 队列 | **先清空**，`append: true` 才追加 | 「跑这个目录下所有序列」混进上一批残留，结果就没法看 |
| `out` | 每段 `<序列目录>/<名字>_成片.mp4` | 一条 `out` 对一批会互相覆盖，扫到多条时直接拒绝 |
| 规格校验 | 整批先校验，再动队列 | 半批入队比一批不进去更难收拾 |
| 渲染 | 走队列同一条 `queue::render_item` | 参数、进度、取消、逐位一致性不另开一套 |

单条与批量共用 `queue_item_from_args` 做参数校验：一个参数只许一套判断（R4 的教训搬到
参数上）。

## 返回结构

```json
{
  "root": "D:/timelapse/2026-11-04", "depth": 1,
  "scanned": 3, "queued": 3, "cleared": 0,
  "ok": 2, "failed": 1, "cancelled": false,
  "items": [
    {"index": 1, "root": ".../a_first", "out": ".../a_first_成片.mp4", "status": "完成", "note": ""},
    {"index": 3, "root": ".../c_broken", "out": ".../c_broken_成片.mp4", "status": "失败",
     "note": "打开序列失败：这些文件里有我们解不开的格式"}
  ],
  "skipped": [{"root": ".../d_bad", "reason": "这些文件里有我们解不开的格式"}]
}
```

`items` 与 GUI 队列面板同源（`render_queue.json`），所以跑完打开 GUI 看到的是同一份状态。

## 无人值守

`background: true` 立即返回，进度查 `aevum_queue_status`，取消用 `aevum_queue_cancel` /
`aevum_cancel`。判据 `tools::batch_run_covers_a_directory_and_names_the_broken_sequence` 钉
三件事：两段真的落了成片文件（不是「自报成功」）、坏的那段状态是「失败」且 `note` 有一句
人能读的原因、默认清空上一批（`cleared` 等于上一批段数）。

## 边界

- 不删源图、不改源图（与所有工具同一条底线）；失败段留下的中间帧按队列规则保留。
- 扫不到序列直接报错，不返回空清单——空清单会让调用方以为「跑完了，0 段」。
- 只编排「已经是一条序列」的目录：素材筛选（评级/旗标）仍走 `aevum_cull_*`，两者不越界。
