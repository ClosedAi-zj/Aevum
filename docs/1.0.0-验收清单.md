# 1.0.0 验收清单（Definition of Done）

> 冻结时间：2026-10-31　适用版本：`v1.0.0`（从 `v0.5.0-beta.2` 出发）
> 本文件是 1.0.0 的**唯一验收口径**。任何一个阶段结束时，只按本文件判定能不能进下一阶段；
> 阶段内的技术选择由执行者定，判定标准不因实现方便而放宽。

## 0. 立场

1.0 的含义不是"功能更多"，而是**三件事同时成立**：

1. **不丢用户的活**——任何会让改动静默丢失、写错位置、存不进去的路径，都必须有可读的提示与明确的落点；
2. **能对外承诺**——工程格式、预设、命令行参数、MCP 工具集四者各自的兼容策略写清楚，且"正式版"三个字不与文档里的"beta 期不承诺"自相矛盾；
3. **可复现地交付**——任何人拿到 tag 都能用同一条命令打出与发布资产逐字节可校验的包，产物自身合规（含许可），版本号不会靠人肉同步。

不满足以上三条的任何一条，1.0.0 不发。

## 3. 阶段划分与出口

每个阶段结束**必须**满足：① 单独 commit（一个功能一个 commit，不合并提交）；② `scripts/check.sh` 四关全绿；③ 本阶段所有阻断项给出上表要求的证据；④ 团队评审通过。任一条不满足，不进下一阶段。

| 阶段 | 内容 | 出口 |
|---|---|---|
| S1 | 冻结本清单 + 让 `docs/` 可选择性入库 | 本文件入库；`.gitignore` 改用 `docs/*` + 负向规则 |
| S2 | 数据安全类：B2（只读盘提示）、B3（便携 override 诊断） | 两条各自有测试；只读盘场景可复现演示 |
| S3 | 算法类：B1（降噪 eps）+ oracle 同步重冻结 | `fit_denoise` 达标；`develop_golden` 47 case 全过；冻结跑两遍逐字节一致 |
| S4 | 交付链路：B4（脚本化打包 + LICENSE + 校验和）、B5（版本一致性检查）、B8（ffmpeg 探测）、B9（toolchain） | 一条命令出包；`sha256sum -c` 通过；门槛能拦住版本号漂移 |
| S5 | 对外文档与承诺：B6、B7、N1-N9 的披露 | 发布说明完整；中英 README 一致；`grep 'beta 期不承诺'` = 0 |
| S6 | 1.0.0 发版：bump、冻结、打包、tag、release、回填 | 发布资产可下载且 sha256 与本地一致；CI 绿；回滚路径写在发布说明里 |

## 4. 每阶段的门（固定动作）

1. `bash scripts/check.sh` → EXIT=0（格式 / clippy -D warnings / 全量测试 / 界面自检）。
2. 涉及数值的改动：先跑基线并记录，再改，再对比；**验收口径在实施前冻结**，不许改断言去适配实现。
3. 涉及金标的改动：Rust 实现、Python 参考实现、金标数据、验收阈值**四处同步**，缺一不可；重冻结后跑第二遍确认逐字节一致。
4. 涉及落盘格式（工程 JSON / 预设）的改动：`project_roundtrip` 与旧工程回归必须过；新字段一律 `serde(default)`。
5. UI 改动：`--selftest` 形状数变化必须在提交信息里说明是"预期变化"还是"回归"。

## 5. 发布流程（S6 执行）

1. 全绿门槛 → `cargo build --release` → `scripts/package.sh` 产出 zip + `SHA256SUMS`。
2. **在解压出的产物上**跑 `--selftest` 与一次真实导出（`package.sh` 已含），形状数与构建树一致。
3. `Cargo.toml` 版本号 bump 到 `1.0.0`，同步 `Cargo.lock`、README 四处、CHANGELOG 新节、发布说明。
4. 打注解 tag `v1.0.0`，推送提交与 tag（本机 `github.com:443` 不通，用 Git Data API 重放，验收标准是远端 sha 与本地逐字节相等）。
5. 建 GitHub Release（`prerelease: false`）并上传 zip + `SHA256SUMS`，用 API 返回的 `digest` 与本地 sha256 对齐。
6. 下载资产回验 sha256；把回验结果写进发布说明的「验收数据」节。

## 6. 回滚

- 程序：换回 `v0.5.0-beta.2` 的包即可；1.0.0 不改变工程目录、配置目录与工具名。
- 工程：1.0.0 若引入新字段，一律 `serde(default)`，旧版打开只丢新字段的**增量**，不报错。
- 承诺：若 1.0.0 之后发现阻断性缺陷，发布 `1.0.1` 修复；不撤 tag、不改已发布资产（资产与 tag 必须对应，这一点 beta.1 吃过亏）。

## 7. 变更控制

- **一功能一 commit**：每个阻断项至少一个独立 commit，提交信息写"改了什么/为什么/怎么验证"。
- 阶段之间由队长评审：看 diff、看证据、看是否夹带无关改动；不通过则退回本阶段，不进入下一阶段。
- 卡死判定：同一阶段同一问题**两次尝试无新证据**即换路径；换路径仍不行，降低范围并把未完成项写进 §2（必须标注"未完成"而非"已知限制"）。
