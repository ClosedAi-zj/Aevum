## 4. 四项拍板与工程含义

1. **三批全做，分批分次发版**。→ §5 的三批即三个发版边界；每批独立过六关，不攒大提交。
2. **缩略图曝光差异：保留性能取舍**。保留 128 px 内嵌原片，加可见「原片·未显影」标记并说明口径；
   **不碰显影链、不动缓存键、不伤首屏 300 ms 预算**（`preview_budget.rs:18-40`）。否决 R16 的
   「强制一致」改造。
3. **播放变模糊：代理 + 标记 + 自动回切**。播放中使用较大尺寸代理并标「快速预览」，暂停/结束
   自动切回 1600 边全质量已显影预览；草图/全量两档槽位隔离，不许草图污染全量像素
   （`preview_budget.rs:95-106`）。
4. **调色面板：只调视觉质感**。字阶收敛、分组分隔对比、滑块三列对齐、数值等宽右对齐、
   曲线网格主次线；**不动已实现的 ACR 九分区信息架构，不碰 `GROUP_SPECS` 键名与
   `Module::ALL` 序号契约**（ACR 化文档 `:105-116`）。否决 R17 的信息组织重构。

## 5. 三批实施顺序与可测验收口径

**每批共同出口**：`bash acceptance/check.sh` 六关全绿、`--selftest` 形状数对照、i18n 中英成对
（`i18n_coverage` 会红）、每条新增判据做过变异验证（红得准才算）、小步提交、单独发版。

### 第一批 · P0：6 条确定性缺陷 + 显眼性 2 项

顺序：D2 → D3 → D4 → D1 → D5 → D6 → **D7 → D8**（先修会静默破坏参数的，再修布局与呈现，
最后处理「做了但看不见」）。

> **批次调整留痕（2026-11-05 真机复核后）**：原方案把「胶片条收起」与 `×` 语义放在第二批
> 表达层，理由是「功能已存在、只调可发现性」。用 v1.9.7 正式包真机出图复核后推翻该判断：
> 收起入口位于 1600 px 宽度的最右端，是「曲线　﹀　胶片」几个 dim 灰字，箭头仅 10 px、
> 无边框无底色（`timeline.rs:44-46` 注释原文「降为 ghost：头部行是说明，不是按钮排」）——
> 实现口径与用户「要一个按钮」的要求相反，不是「调亮一点」能补救的。故 D7/D8 升入第一批。

- **D2 滑块滚轮**：滚动容器 20 次、指针全程划过 5 个滑块，5 个参数值前后逐位 diff = 0；
  滚轮只改变容器滚动位置；调值仅由拖拽手柄 / 点击轨道 / 双击复位 / 键盘（需显式聚焦）触发，
  无聚焦时滚轮不改变任何值。`common.rs:739-745` 的 hover 滚轮分支移除后，把该分支写回 →
  判据必须红。
  **设计意图变更（留痕）**：工作区 `UI设计方案-LUMEN-STUDIO-v1.0.md` §9 验收清单第 3 条
  原把「滚轮」列为参数行七项交互之一（拖动 / 双击复位 / Alt 精调 / **滚轮** / 键入 / Esc /
  非法回弹）。用户 2026-11-05 实测反馈「滑动时容易误触、直接调节，不能使用滑轮调整」，
  且这一诉求为拍板口径，**推翻旧设计条款**：滚轮从「调值入口」降为「只滚动容器」。
  按显式聚焦后方向键 / 双击数值框键入替代。该旧条款视为已废弃，不再作为验收依据。
- **D3 裁剪历史**：**先写复现用例，再定位根因；不预设成因、不否认用户所见**（架构师未找到
  「单次连续拖动产生 10 条」的复现路径，现有 `crop-drag` 固定键 + 30 UI 帧窗口 + 3 条判据，
  但用户截图 91–100 确实是 10 条）。验收：① 存在一条能稳定复现或证伪的自动化用例，记录
  「单次连续拖动 → 历史新增 N 条」；② 定位后一次裁剪从按下到松开历史净增 = 1 条、拖拽
  中间每帧净增 = 0 条；③ 连续 10 次独立裁剪 → 恰好 10 条；④ 一次撤销回到裁剪前状态。
- **D4 画布缩放**：任意缩放级别（含超出视口）下，图像四向与视口边界留白 ≥ `spacing` token
  指定值，几何中心与视口中心偏差 ≤ 1 px；除主动平移外无边缘裁切；顶部信息条不被图像覆盖。
- **D1 字阶收敛**：`toolbar.rs` 同一行内 `SIZE_*` 取值集合 ≤ 2 种且 100% 来自 `theme.rs`
  现有字阶；`crates/aevum-ui/tests/suite/ui_tokens.rs` 扩条目（字阶有序 + 混用检查），
  **不新建主题体系**；把一处改回第 3 种 `SIZE_*` → 判据必须红。
- **D5 播放预览**：播放中显示「快速预览」标记且使用较大尺寸代理（非 128 边缩略图）；
  暂停/结束后 ≤ 1 个刷新周期切回 1600 边全质量已显影预览；播放期间不出现瞬时模糊跳变；
  `preview_budget.rs` 两条判据（草图 ≤ 300 ms、草图不污染全量像素）保持全绿。
- **D6 发布说明**：检查更新窗口内原始 Markdown 源文本字符数 = 0；渲染后含版本号 / 日期 /
  分组列表 / 链接四类结构化元素；中英成对；不做完整 Markdown 引擎（轻量渲染即可）。
- **D7 胶片条收起按钮（升入第一批）**：收起入口从头部最右端移到**头部左端**、紧跟
  「胶片条 · N 帧」标题之后，做成**带描边 + 底色的真按钮**（宽 ≥ 96 px、高 ≥ 24 px），
  文案随状态切换「收起预览 / 展开预览」（中英成对），带 Chevron 图标，hover 抬起；
  默认态**不得**是 `dim()`。点击语义仍是 `state.show_film` 取反，收起后主画布高度增加、
  恢复后选中帧 / 滚动位置 / 星级筛选状态不变。
- **D8 关闭与删除类控件（升入第一批，同类问题）**：文档页签的裸「✕」（`toolbar.rs:180-190`，
  默认 `dim()` + MICRO 字号）改为有语义的图形、默认态不低于 `muted()`、补 hover 说明；
  分组头折叠箭头（`common.rs:308-313`）、分组复位（`:435-441`）、快照删除（`windows.rs:918-928`）
  等同类 ghost 控件一并提亮。判据：`visual_consistency.rs::destructive_controls_are_not_dim_by_default`。

### 第二批 · 表达层：8 项

- **E1 胶片条收起（已升入第一批 D7）**：见 D7。本条保留仅为编号连续性，施工以 D7 为准。
  旧口径「不新增按钮、只调 chip 对比度」**已作废**——真机复核证明那正是用户看不见的原因。
- **E2 缩略图标记**：每个缩略图有可见「原片·未显影」标记与口径说明（中英成对）；
  128 边内嵌原片路径、缓存键、显影链零改动；首屏 300 ms 判据保持全绿。
- **E3 顶部信息条**：按「文件名 / 画幅 / 位深 / 序列帧数」标签化，画幅带明确单位；
  `×` 不再以 `danger()` 小字单独出现引发关闭误读；术语表统一；5 人 10 秒辨认测试
  ≥ 4 人能说出「4000 × 6000 是画幅尺寸、不是关闭按钮」。
- **E4 统计口径**：百分比标注统计口径（显影后像素 / 全帧或选区 / 阈值）；自动曝光展示
  改动项与前后数值；「全部复位 / 导入 XMP / 导出 XMP」写明作用范围；真实计算路径零改动。
- **E5 子窗口与按钮**：不新增浮窗 shell 实现，现有 `ui_tokens.rs` 九条守门保持全绿；
  分组分隔对比度提高且走 `soft_rule` / token；同类按钮圆角 / 描边 / 高度 / 内边距
  100% 来自现有 control token。
- **E6 版本状态自证**：窗口显示本地版本 / 远端版本 / 最近一次检查时间 / 检查来源四项；
  「已是最新版本」只在真实比对成功后显示，失败或未检查为中性态（含重试入口）；
  `brand::version()` 唯一读取点不变。
- **E7 单帧播放语义**：`frame_count() >= 2` 才启用播放 / 暂停 / 下一帧；单帧或 0 帧为禁用态
  并带 tooltip「载入 ≥ 2 张后可播放序列」；文案改「播放序列 / 暂停序列」，中英成对。
