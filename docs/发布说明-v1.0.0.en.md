# Aevum Studio 1.0.0 release notes

[中文](发布说明-v1.0.0.md) · **English**

Released: 2026-10-31
Previous version: `0.5.0-beta.2`

---

## In one sentence

**A stable release is not about more features — it is three things holding at once**: user work is
not lost (paths that cannot be written, or that would silently drop an edit, now produce a readable
notice and a definite destination), the external promises are explicit (project format / presets and
parameters / command-line arguments / MCP tools, each stated separately), and delivery is
reproducible (one command produces the package, and the artefact can be verified byte-for-byte).

Compared with `0.5.0-beta.2`, **the only change that touches pixels is the `eps` of multi-scale
denoise**; everything else is delivery plumbing and documentation.

---

## Upgrade notes (three sentences)

1. **Install over the top**: unzip the new package and replace the old folder — there is no
   installer and no migration step.
2. **Project and config directories stay put**: `<sequence>/.aevum/` and `%APPDATA%/aevum-studio`
   are read in place, existing projects open directly, and parameters, ratings, flags, keyframes
   and camera moves carry over untouched.
3. **The 1.x compatibility promise is in the README section "Versioning"** (Chinese: 「版本方案」),
   with all four contracts spelled out; the same promise in summary form is at the top of
   `CHANGELOG.md`.

## 1. Changes in this release

### Algorithm: multi-scale denoise `eps` aligned with real noise (the only algorithm change)

The old formula treated `eps` as a "contrast threshold" rather than a "noise variance", producing 86×
the noise variance at σ=0.02, so structures with low variance (stars, texture) were classified as
noise and flattened. With `eps = 0.8·σ̂²/rm`, `eps` returns to variance units and `1/rm` compensates
for scale. (Criterion: `docs/adobe-algorithm-atlas.md` §46.2 — noise variance down > 50% while MTF
stays > 85%; measuring position pinned to 1024×768.)

| Frame size | Multi-scale before (variance↓ / MTF) | Multi-scale after |
|---|---|---|
| 512×256 (degenerate frame, not used for judgement) | 72.0% / 64.2% | 26.7% / 93.6% (insufficient denoise) |
| **1024×768 (measuring position)** | 74.5% / 44.6% | **53.8% / 90.0% — passes** |
| 1536×1152 | — (first measured this round) | **62.7% / 87.3% — passes** |
| 2048×1536 | 74.9% / 48.7% | **60.3% / 89.5% — passes** |

**How it looks now**: with "multi-scale" on, the result **preserves more texture than before and
leaves slightly more noise**. Previously it was "half the detail for cleanliness"; now it grinds as
much as the noise variance calls for. The cost, stated plainly: at the same `nr_luma` setting, total
denoise with multi-scale is lower than pure single-scale (1024×768: 53.8% vs 69.4%), in exchange for
5.5 points of MTF. The single-scale branch was not touched by a single byte in this release.

### Delivery chain

- `scripts/package.sh` produces the package in one command: gate → release → bundled ffmpeg →
  self-test → real export → zip (top-level directory, containing `LICENSE` and `CHANGELOG.md`) →
  `SHA256SUMS` → unzip and re-verify the self-test shape counts.
- ffmpeg probing became a reproducible three-step chain (`AEVUM_FFMPEG_SRC` → bundled
  `tools/ffmpeg.exe` → `PATH`), and the dead script pointing at a non-existent venv was deleted.
- The acceptance system became its own `acceptance/` directory (`reference/` for the reference
  implementation, `oracle/` for frozen goldens, `check.sh` for the gate), separated from product
  code.
- Version consistency became gate step 0 (`acceptance/check_version.py`): `Cargo.toml` is the single
  source of truth, and `Cargo.lock`, the four README positions and the newest CHANGELOG heading must
  agree.

### Documentation and promises

- Both README language sections replaced "no promise during beta" with the four 1.x compatibility
  contracts, and each gained an "Upgrading from 0.5 beta" subsection.
- The beta-era statement at the top of `CHANGELOG.md` was rewritten in step.
- This file is new, consolidating the known limitations in one place (see below).

### Already delivered in beta.2, unchanged here

`xmp` tool routing in attach mode; error messages that distinguish "only available in server mode"
from "unknown tool"; three tool lists collapsed into the single source of truth `mcp_routes`;
readable errors when `.aevum` is occupied by a file of the same name; `--attach` version mismatch no
longer putting extra commands into `tools/list`; the output-sharpening overshoot clamp (8.35% →
2.09%). Details in the `v0.5.0-beta.2` section of `CHANGELOG.md`.

## 3. Known limitations

The nine items below do not block 1.0, but all of them are things users can hit, so they live here
rather than scattered across CHANGELOG entries.

1. **Demosaic defaults to `cell_average`**; the direction-adaptive algorithm is implemented but **not
   enabled by default**. It can be switched in the diagnostics panel, and **it resets on restart**
   (no persistence). The default stays conservative; 1.0 does not change it.
2. **HDR export (PQ / AVIF 10-bit) is not implemented**; the UI has a reserved entry point only — do
   not treat it as a working feature.
3. **AI denoise is experimental**: no numeric golden, no objective acceptance. Do not use it to make
   delivery decisions.
4. **Performance has no CI assertion, only manual readings**: shared-runner jitter would turn the
   gate into noise, so the bench records numbers without enforcing them. The 1.0.0 readings are in
   the table above (with methodology and machine configuration): frame time 0.57–0.79 ms, p95 no
   higher than 1.26 ms, roughly 21× headroom against the 16.7 ms budget for 60 fps. Two things
   stated plainly: (a) M1's **fingerprint cache hit path is about 2× slower than raw JSON parsing**
   (0.81 → 1.54 µs) — a known item recorded before `0.5.0-beta.1`, not introduced here; it is
   amortised by computing it once per frame (`mask_prep`), and the frame-level gain already covers
   it; a real fix needs the fingerprint pushed down into incremental updates. (b) These numbers are
   only comparable on this machine — do not compare across machines.
5. **Real-footage end-to-end tests skip when the footage is missing**: cases that cannot run on CI
   must be run once locally by the releaser, with footage present.
6. **The exe is not code-signed**, so Windows shows a SmartScreen prompt on first run ("More info →
   Run anyway"). Self-verification: check the downloaded zip against `dist/SHA256SUMS`.
7. **The name `lapse` survives only in user data**: the `.lapse/` project directory and the
   `lapse-studio` config directory are still read and still migrated (compatibility layer — must not
   be removed); the Python reference implementation in the repo has moved to
   `acceptance/reference/` and no longer borrows that historical name.
8. **`打包.bat` has been deleted**: it pointed at a `.venv` that no longer exists. Packaging goes
   through `scripts/package.sh` only.
9. **Most of `docs/` is not in version control**: only the release notes and the 1.0.0 acceptance
   checklist are tracked (`.gitignore` uses `docs/*` plus negation rules); the remaining process
   documents stay local.

## 4. Rollback

- **Program**: switch back to the `0.5.0-beta.2` package
  (`dist/Aevum-Studio-v0.5.0-beta.2-windows-x64.zip`, sha256
  `c082f159b8b741ca1cd71e7b104b5452cda7f15af40996edaa5caa835187b25a`).
- **Project and config need no moving**: 1.0 changes neither the project directory (`.aevum/`) nor
  the config directory (`%APPDATA%/aevum-studio`), nor tool names or CLI arguments, so the older
  build opens everything as usual.
- **What you lose**: new fields written by 1.0 are ignored by beta.2 — exactly the direction the
  compatibility promise states (an older build reading a newer project drops only the new fields,
  with no error). The parameters themselves are not lost.
- **Promise**: if a blocking defect is found after 1.0.0, ship `1.0.1`. Never delete a tag and never
  modify a published artefact.
