## 1. What problem it solves

The two classic landscape-timelapse composites are both possible in PS, and both are manual:

- **Sky and ground**: sky from the frame after sunset (clouds still coloured, ground black),
  ground from the brightest frame (ground still has detail). In PS: stack two layers, brush a
  mask, then bend a curve at the seam. A new set of frames means a new mask.
- **Time slice**: cut the frame into horizontal bands, each taken from a different moment, so
  the clouds stretch into a continuous span of time. In PS: duplicate N layers, mask each one
  with a rectangle, then fix every seam by hand.

The shared cost is not the algorithm, it is **starting over every time**. AEVUM splits it into
three separately verifiable steps: frame selection, feathering, exposure matching. Once it is
parameterised, a new set of frames is just new frame numbers.

## 2. Reverse-engineering evidence (how PS actually does it)

Source: Photoshop 2025 (`D:\app\ps\Adobe Photoshop 2025\Photoshop.exe`, 201,268,720 bytes,
sha256 `f0fd8c6c20089511…`). Three independent, checkable paths:

### 2.1 Shipped script (E2)

`Presets/Scripts/Statistics.jsx` (184 lines) maps the 11 statistical modes onto ClassIDs:

| Menu mode | ClassID | statistics.8ba export |
|---|---|---|
| Mean | `avrg` | `MEAN_ENTRY` |
| Sum | `summ` | `SUM_ENTRY` |
| Minimum | `minn` | `MIN_ENTRY` |
| Maximum | `maxx` | `MAX_ENTRY` |
| Median | `medn` | `MEDIAN_ENTRY` |
| Variance | `vari` | `VAR_ENTRY` |
| Standard deviation | `stdv` | `STDDEV_ENTRY` |
| Skewness | `skew` | `SKEW_ENTRY` |
| Kurtosis | `kurt` | `KURT_ENTRY` |
| Range | `rang` | `RANGE_ENTRY` |
| Entropy | `entr` | `ENTROPY_ENTRY` |

The script layer calls `applyImageStackPluginRenderer` with the class `imageStackPlugin`, and
`CreateImageStack.jsx` builds the layer stack. **So PS "statistics" is not a layer blend mode:
it is a separate plug-in that reads pixels frame by frame and computes a statistic per pixel** --
which is why its result differs from setting layers to 50% opacity.

### 2.2 Plug-in export table plus decompilation (E1)

`Required/Plug-ins/Image Stacks/statistics.8ba` (PE32+ DLL, 102,384 bytes) exports 11 named
entry points; Ghidra decompilation confirms the addresses:

`MEAN@d1f0` `SUM@db40` `MIN@d520` `MAX@d070` `MEDIAN@d3a0` `VAR@dcc0`
`STDDEV@d9b0` `SKEW@d820` `KURT@cee0` `RANGE@d6a0` `ENTROPY@cd50`

Every entry has the same shape: `NewHandle(0x38)` allocates a 56-byte context, then
`switch(mode)` dispatches. **The same mode word means different things in different entries**
(`MEDIAN_ENTRY` case 1 → `FUN_18000ae00`, `MEAN_ENTRY` case 1 → `FUN_18000a900`), so the
dispatch value is the **bit depth / channel format** (8 / 16 / 32 bit), not the statistic. Each
export handles one statistic and internally splits into three code paths by depth.

The tiling strategy is hard-coded and worth copying:

- width `w` clamped to `[1, 2_000_000]`;
- height `h = (int)sqrt(buffer_bytes / (width * 2 + 2))`, clamped to `[16, 1024]`;
- depth steps 8 → 0x10 → 0x20 decide bytes per pixel.

The import table holds **only host API and CRT memory functions**: `PLUGIN.dll`'s `NewHandle` /
`HostAllocateBuffer` / `HostLockBuffer` / `HostFreeBuffer` / `BlockMove` /
`WarnHostBufferProcsAvailable` / `WarnHostAdvanceState`, plus `memcpy` / `memmove` / `memset`
from `MSVCP140` / `VCRUNTIME140`. **No `qsort`, no math library** -- so the median must be
inlined in the pixel loop (selection or insertion on a tiny array, not sorting the whole stack).

Left blank (not found, not invented): whether the median uses a histogram or a selection
algorithm, whether 32-bit documents run entirely in linear light, and how SIMD is unrolled.
None of these affects our choice.

### 2.3 Local reverse-engineering library (E1/E2)

`E:/code/ps-lr/docs/adobe-algorithm-atlas.md` section 33 (multi-exposure merge) documents the
ACR chain:

1. `ExposureNormalize` -- normalise each frame's exposure gain first;
2. `ComputeDeghostMap` -- compute a robust median **at low resolution** as the ghost-free
   reference;
3. `SoftenDeghostEdges` -- soften the deghost labels;
4. `PipeNearestResampleDeghostLabels` -- **nearest-neighbour** upsample back to full resolution;
5. `BlendWithBlurredMask` / `weighted_add` -- blend by weight.

Steps 2 and 4 are the interesting part: a mask at full resolution is both expensive and noisy,
while computing it small and upsampling with nearest-neighbour is steadier. **This version does
not deghost** (see section 8), but the names are reserved along that chain.

## 3. Layer blend formula and the gamma-domain trap

PS layer blending (including opacity) is:

```
Co = (1 − αb)·Cs + αb·[(1 − αs)·Cb + αs·B(Cb, Cs)]
```

where `B` is the blend function: Lighten = `max`, Darken = `min`, Screen = `1 − (1−a)(1−b)`,
Multiply = `a·b`. With αs = 1 and αb = 1 it reduces to plain `B(Cb, Cs)`.

**The trap is averaging.** Because `γ` is concave, Jensen's inequality gives, for a per-pixel
mean taken in a gamma domain:

```
mean(γ(x)) < γ(mean(x))
```

That is: the result is systematically darker, and shadows and stars smear first. This is one of
the main reasons "it never quite looks right in PS". So `stack.rs` and `timeblend.rs` **run
entirely on linear f32**, and the develop chain comes afterwards -- never grade each frame
first, which would stack two nonlinear curves and make the seam impossible to align.

## 4. Our implementation

### 4.1 Three steps

| Step | What it does | Parameters |
|---|---|---|
| Select | `Layout::SkyGround` splits at the horizon (sky from the last frame, ground from the first); `Layout::Bands` lays the whole frame out from early to late by band count | `layout` `bands` `horizon` |
| Feather | Band edges use smoothstep `3t²−2t³`; the two sides of a boundary **always sum to one** | `feather` (fraction of image height, default 0.04) |
| Match | Align each source frame to the reference by full-frame median brightness, gain clamped to ±2 EV | `match_exposure` (default on) |

### 4.2 Two invariants

1. **Weights always sum to one**: `s(t) + s(1−t) = 1` (smoothstep's symmetry). Overlapping
   never brightens or darkens. `band_weights_always_sum_to_one_across_a_boundary` sweeps it
   row by row.
2. **Outer edges are pinned to 1**: the top edge of the first band and the bottom edge of the
   last are **frame borders**, not seams, so their weight must be a flat 1. This one was a real
   bug caught by the test: the first version gave the top band only 0.84 weight with no second
   band to make up the difference, and the top row came out dark (see commit `f9efe60`).

### 4.3 Details of exposure matching

- Median brightness: linear, averaged over RGB, **at most 4096 samples** sorted (sorting 45
  million numbers from a 45MP frame is pointless).
- Reference is `frames[len/2]` (the middle frame): the first frame skews bright, the last
  skews dark, the middle is steadiest.
- Gain `clamp(reference / source, 0.25, 4.0)` = ±2 EV; a near-zero or non-finite source skips
  matching entirely (better unmatched than amplified into a field of noise).

## 5. Four key decisions

1. **Linear domain**, see section 3.
2. **smoothstep rather than a linear ramp**: a linear ramp has a first-derivative
   discontinuity at its knees, which reads as a hard edge on screen; smoothstep has zero
   derivative at both ends so the transition is invisible. The cost is that the transition is
   twice as wide, so `feather` is a **half-width**.
3. **MAD rather than standard deviation** (also used by the cull station): on a sunset ramp a
   standard deviation reads "the light is changing" as "large spread", and a few genuinely bad
   frames widen it further -- the two effects cancel out. The MAD only looks at the middle
   half, so the band tightens back.
4. **No per-frame grading**: once every frame goes through a curve first, two nonlinearities
   stack and the seam can no longer be aligned. Compositing must happen on raw linear pixels.

## 6. What the tests pin down

Seven core signals (`crates/aevum-core/src/timeblend.rs::tests`):

| Signal | What it pins |
|---|---|
| `band_weights_always_sum_to_one_across_a_boundary` | the feathering invariant, swept row by row |
| `a_single_band_is_the_identity` | one frame / one band is bit-identical |
| `time_slice_puts_early_frames_on_top_and_late_ones_at_the_bottom` | frame order is not reversed |
| `sky_ground_splits_at_the_horizon_without_a_step` | with equal frames the output equals them everywhere (feathering cannot invent brightness) |
| `exposure_matching_removes_the_seam_a_stop_apart_two_frames_would_show` | one stop apart does show a step, and matching removes it (**with a negative control**) |
| `exposure_matching_is_clamped_so_a_black_frame_cannot_blow_up` | the gain clamp |
| `degenerate_inputs_are_reported` | empty / zero size / mismatched sizes |

One end-to-end signal (`crates/aevum-ui/src/state.rs`):
`timeblend_merge_splits_sky_and_ground` -- it really writes an image, really puts the last
frame in the lower half, and checks three rejection paths (confirm, out-of-range bands,
unknown layout).

## 7. Defaults and why

| Parameter | Default | Reason |
|---|---|---|
| `layout` | `sky-ground` | The common case; band slicing is the advanced mode |
| `bands` | 8 | Eight bands on screen: each is visibly "another moment"; more turns into stripes |
| `feather` | 0.04 | About 40 px at 1000 px height: hides the seam without smearing cloud structure |
| `horizon` | 0.5 | Most compositions put it near the middle; draggable in the UI |
| `match_exposure` | on | Frames from different moments sit stops apart; unmatched always steps |
| `MAX_FRAMES` | 32 | Band cap is 32; beyond that each band is only a few rows tall |

## 8. Known gaps (next round)

1. **Deghosting**: right now a moving object (clouds, trees, traffic) smears across band
   boundaries. The ACR recipe (low-resolution robust median → soften → nearest-neighbour
   upsample → blend) is recorded in section 2.3, and `Spec` has room for a switch that is not
   implemented yet.
2. **Automatic sky segmentation**: currently one horizontal line. The real thing is a soft
   split on gradient or colour, and `mask.rs` already has linear / radial / brush components to
   reuse.
3. **Full-resolution preview**: today you must composite (and write a file) to see the result.
   The panel should preview at half resolution and react to parameter changes immediately.
4. **"Extract a subsequence" in the cull station**: today it only flags rejects; there is no
   "write the kept frames into a new sequence folder". That needs bulk writes and path safety,
   so it gets its own round.
