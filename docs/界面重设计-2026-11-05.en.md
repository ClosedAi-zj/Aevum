**Triage map**: 14 feedback items -> **6 deterministic defects** (D1-D6) /
**8 already built, expression only** (E1-E8) / **3 capability gaps** (C1-C3).

**Conclusion**: no second theme system, no ACR panel re-layout, no floating-window shell
rewrite. Batch 1 fixes the six deterministic defects and makes the gates go red first;
batch 2 makes already-built things legible; batch 3 adds the three capabilities.

## 4. Four decisions and their engineering consequences

1. **All three batches ship, in separate releases.** -> The three batches in §5 are three
   release boundaries; each passes the six gates independently, no large combined commit.
2. **Thumbnail exposure difference: keep the performance trade-off.** Keep the 128px embedded
   original, add a visible "Original · Undeveloped" badge and state the convention;
   **do not touch the develop chain, do not change cache keys, do not hurt the 300 ms
   first-screen budget** (`preview_budget.rs:18-40`). R16's forced-consistency rebuild is rejected.
3. **Playback blur: proxy + badge + automatic switch-back.** Use a larger proxy during playback
   with a "Fast preview" badge; on pause/end switch back automatically to the full-quality
   1600px developed preview; the sketch/full slots stay isolated so the sketch cannot pollute
   the full output (`preview_budget.rs:95-106`).
4. **Grading panel: visual quality only.** Consolidate type scale, group separator contrast,
   three-column slider alignment, right-aligned monospaced values, primary/secondary curve grid;
   **do not touch the implemented ACR nine-section information architecture, `GROUP_SPECS`
   key names or the `Module::ALL` index contract** (ACR plan `:105-116`). R17's information
   architecture rebuild is rejected.

## 5. Three batches and measurable acceptance criteria

**Shared exit for every batch**: `bash acceptance/check.sh` six gates green, `--selftest` shape
counts compared, i18n strings paired in both languages (`i18n_coverage` goes red otherwise),
every new gate proven by mutation testing (only a *correct* red counts), small commits,
one release per batch.

### Batch 1 · P0: six deterministic defects + two visibility items

Order: D2 -> D3 -> D4 -> D1 -> D5 -> D6 -> **D7 -> D8** (fix whatever silently corrupts
parameters first, then layout and presentation, then "built but invisible").

> **Batch change (recorded after real-app review, 2026-11-05)**: the original plan put the
> filmstrip collapse control and the `×` semantics in batch 2 as "feature exists, just tune
> discoverability". Rendering real screenshots from the shipped v1.9.7 package overturned
> that: the collapse entry sits at the far right of a 1600 px row, rendered as a few `dim()`
> words "曲线 ﹀ 胶片" with a 10 px chevron and no border or fill (`timeline.rs:44-46` comment:
> "降为 ghost：头部行是说明，不是按钮排"). The implementation's intent is the opposite of the
> user's "there should be a button", so brightening the chip cannot fix it. D7/D8 move up.

- **D2 Slider wheel**: scroll the container 20 times with the pointer crossing 5 sliders; all
  5 values are bit-for-bit unchanged (diff = 0); the wheel only moves the container scroll
  position; values change only via dragging the handle / clicking the track / double-click
  reset / keyboard (with explicit focus); with no focus the wheel changes nothing.
  After removing the hover-wheel branch at `common.rs:739-745`, writing that branch back must
  turn the gate red.
  **Design-intent change (recorded)**: section 9, item 3 of the workspace document
  `UI设计方案-LUMEN-STUDIO-v1.0.md` originally listed "wheel" as one of the seven parameter-row
  interactions (drag / double-click reset / Alt fine-tune / **wheel** / typing / Esc / invalid
  rollback). On 2026-11-05 the user reported from real use that scrolling accidentally changes
  values and explicitly required the wheel not to adjust them. That ruling **supersedes the old
  clause**: the wheel now only scrolls the container. Explicitly focused arrow keys and typing
  into the value field replace it. The old clause is deprecated and no longer an acceptance basis.
- **D3 Crop history**: **write a reproduction case first, then locate the root cause; do not
  presume a cause, and do not deny what the user saw** (the architect found no reproduction
  path for "one continuous drag producing 10 rows"; the fixed `crop-drag` key, 30 UI-frame
  window and 3 gates exist, yet the user's screenshot really shows 10 rows at 91-100).
  Acceptance: (1) an automated case that reliably reproduces or disproves it exists and
  records "one continuous drag -> N new history rows"; (2) after root-cause work, one crop from
  press to release adds exactly 1 row and every intermediate drag frame adds 0; (3) ten
  independent crops produce exactly 10 rows; (4) one undo returns to the pre-crop state.
- **D4 Canvas zoom**: at any zoom level (including beyond the viewport), padding on all four
  sides is >= the `spacing` token value and the geometric centre deviates from the viewport
  centre by <= 1 px; no edge is clipped except by explicit panning; the top info bar is never
  covered by the image.
- **D1 Type-scale consolidation**: within one row of `toolbar.rs` the `SIZE_*` value set is
  <= 2 variants and 100% comes from the existing `theme.rs` scale; add entries to
  `crates/aevum-ui/tests/suite/ui_tokens.rs` (scale ordering + mixed-use check) with
  **no new theme system**; restoring a third `SIZE_*` variant must turn the gate red.
- **D5 Playback preview**: playback shows a "Fast preview" badge and uses a larger proxy (not
  the 128px thumbnail); on pause/end it switches back to the full-quality 1600px developed
  preview within <= 1 refresh cycle; no instantaneous blur jump during playback; both
  `preview_budget.rs` gates (sketch <= 300 ms, sketch does not pollute full output) stay green.
- **D6 Release notes**: the update window contains zero characters of raw Markdown source;
  the rendered result has four structural element types (version / date / grouped list /
  links); strings paired in both languages; a lightweight renderer is enough, no full Markdown
  engine.
- **D7 Filmstrip collapse button (moved into batch 1)**: move the entry from the far right of
  the header to the **left end**, right after the "胶片条 · N frames" title, and make it a
  **real button with stroke and fill** (>= 96 px wide, >= 24 px tall), labelled
  "收起预览 / 展开预览" by state (both languages), with a chevron, lifting on hover; the default
  state must **not** be `dim()`. Clicking still toggles `state.show_film`; collapsing grows the
  canvas and restoring preserves the selected frame, scroll position and star filter.
- **D8 Close and destructive controls (moved into batch 1, sibling issue)**: the bare "✕" on
  document tabs (`toolbar.rs:180-190`, `dim()` + MICRO size) becomes a semantic glyph, its
  default state is at least `muted()`, and it gains a hover hint; the same treatment applies to
  the group-header chevron (`common.rs:308-313`), group reset (`:435-441`) and snapshot delete
  (`windows.rs:918-928`). Gate: `visual_consistency.rs::destructive_controls_are_not_dim_by_default`.

### Batch 2 · Expression layer: eight items

- **E1 Filmstrip collapse (already moved to batch 1 as D7)**: see D7. This entry is kept only
  for numbering continuity; the earlier wording "no new button, just raise chip contrast" is
  **withdrawn** — real-app review showed that wording was exactly why the entry stayed invisible.

- **E2 Thumbnail badge**: every thumbnail has a visible "Original · Undeveloped" badge and a
  convention note (both languages); the 128px embedded-original path, cache keys and develop
  chain are untouched; the 300 ms first-screen gate stays green.
- **E3 Top info bar**: labelled as file name / frame size / bit depth / sequence frame count,
  with explicit units on the frame size; `×` no longer appears alone in small `danger()` type
  where it reads as a close button; terminology unified; in a 5-person, 10-second recognition
  test >= 4 can say "4000 × 6000 is the frame size, not a close button".
- **E4 Statistical convention**: percentages state their basis (developed pixels / whole frame
  or selection / threshold); auto exposure shows which fields changed and their before/after
  values; "Reset all / Import XMP / Export XMP" state their scope; the real computation paths
  are untouched.
- **E5 Floating windows and buttons**: no new shell implementation; the existing nine
  `ui_tokens.rs` guards stay green; group separator contrast improves via `soft_rule` / tokens;
  100% of corner radius / stroke / height / padding of same-class buttons comes from existing
  control tokens.
- **E6 Version provenance**: the window shows local version / remote version / last check time /
  check source; "Up to date" appears only after a real comparison succeeds; failure or
  "not checked" shows a neutral state with a retry; the single `brand::version()` read point
  is unchanged.
- **E7 Single-frame playback semantics**: play / pause / next frame are enabled only when
  `frame_count() >= 2`; at 1 or 0 frames they are disabled with a tooltip
  ("Load at least 2 frames to play the sequence"); wording becomes "Play sequence /
  Pause sequence" in both languages.
- **E8 Grading panel quality**: nine-section order, `GROUP_SPECS` keys and `Module::ALL`
  indices unchanged (`--selftest` group registry still matches); four checkable outcomes:
  type-scale value set <= existing token tiers, primary/secondary group separator contrast,
  slider "label / track / value" three-column alignment, right-aligned monospaced values;
  primary/secondary curve grid lines defined by the divider token.

### Batch 3 · Capability gaps: three items

- **C1 Star filter**: reuse `aevum_core::library::Filter` + `ProjectFile.ratings`
  (already persisted with `#[serde(default)]`); no second filtering-state semantics; filtering
  by stars neither reorders nor drops frames, the real sequence order is preserved; one-click
  clear; show the current threshold and "showing N / M frames"; filtering affects display only,
  not the sequence, playback or export range.
- **C2 Plugin input scope**: one unified scope selector (current window / file / folder);
  reuse `aevum_open_sequence` / `aevum_sequences_scan` / `aevum_batch_run` under
  **add-only** rules (no changes to existing MCP tool parameters, no unexpected changes in the
  `tools_list.json` snapshot); plugins that do not support the selected scope are disabled with
  a reason tooltip.
- **C3 Export confirmation**: export opens a confirmation dialog before doing anything;
  cancelling produces no file; the dialog **reuses the parameters already at
  `render.rs:826-852`** rather than building a second form; defaults come from the current
  Render page settings and their source is shown; field labels and validation errors are paired
  in both languages.

## 6. Chinese-English glossary

| 中文 | English | Convention |
| --- | --- | --- |
| 画幅 | Frame size | Pixel dimensions W × H; never the vague "window / size" |
| 位深 | Bit depth | 16 bit pipeline; never "16-bit window" |
| 序列 | Sequence | A set of frames; what playback acts on, not a single image |
| 显影 | Develop / developed preview | Preview with grading applied; opposite of an undeveloped original |
| 修剪 | Clipping | Share of pixels clipped in shadows/highlights; strictly distinct from "Crop" |
| 原片·未显影 | Original · Undeveloped | Badge for the 128px in-camera As Shot embedded original trade-off |
| 快速预览 | Fast preview | Larger proxy used during playback; full quality returns on pause/end |
| 播放序列 | Play sequence | Action available only with >= 2 frames; disabled for a single frame |

All new UI strings are paired in Chinese and English, terms follow this table, and
`i18n_en.rs` is updated in step so one concept never gets two translations.

## 7. Non-goals

1. **No ACR grading panel rebuild**: the nine-section information architecture already exists;
   this round adjusts visual quality only (decision 4).
2. **No second token system**: `theme.rs` already has `SIZE_*` / `radius_*` / `rule` /
   `soft_rule` / `paint_chip` / `row_hover`; only the mixed use in `toolbar.rs` is consolidated,
   with added entries in `ui_tokens.rs`.
3. **No changes to the `Module::ALL` index contract or `GROUP_SPECS` key names**: the index is
   an external contract (ACR plan `:105-116`).
4. **No new filmstrip "collapse" button**: it already exists at `timeline.rs:44-79`; improve
   discoverability only.
5. **No floating-window shell rewrite**: `title_frame()` / `soft_sep` plus nine gates already
   guard it.
6. **No second export-parameters form**: reuse the Render page parameters for confirmation.
7. **No changes to project formats or existing MCP tool parameters**: plugin capability is
   added under add-only rules.
8. **No touching the develop chain, cache keys or the 300 ms first-screen budget**; no
   changes to the sketch/full slot isolation.
9. **No papering over false data**: anything found false must be fixed as a function, never
   hidden by wording; no unsourced numbers or unsupported affirmations remain.
10. **No micro-animations** (former R18): they touch the frame-time budget with zero benefit
    this round.
11. **No new dependencies / font files / web stack**, no pixel-level copying of Adobe assets,
    no commercial signing / accounts / telemetry / cloud.
12. **No pixel-perfect mockups and no architecture rewrite**: this round is incremental
    consolidation.

## 8. Risks and guardrails

| Risk | Guardrail |
| --- | --- |
| A new settings/project field loses data when old files are read | Always `#[serde(default)]` (see `aevum-core/src/library.rs:31,44`); old projects fall back to defaults |
| A new string misses its translation | Pair Chinese and English; `i18n_coverage` goes red; `i18n_en.rs` and the glossary move together |
| Bare colours or hard-coded sizes/radii in the component layer | `aevum-ui` always goes through `theme.rs` tokens; the nine existing `ui_tokens.rs` guards keep applying and new code adds no bare colours |
| Chinese-only comments | Bilingual comments (following existing repository style) |
| A green gate that cannot catch the regression | Mutation-test every new gate: deliberately restore the defect -> it must go red and report the line, then revert |
| Playback/thumbnail work slows the first screen | Frame-time budget in `crates/aevum-ui/tests/suite/preview_budget.rs`: sketch <= 300 ms, sketch does not pollute full output, two isolated slots; all three green to pass |
| Version and doc drift across separate releases | Every batch passes `bash acceptance/check.sh` six gates on its own; this file and its English twin are constrained by the bilingual cross-links in `acceptance/check_docs.py` |

**Close-out**: all 14 feedback items have an owner, all 17 work items have a batch and a
measurable criterion; the three audit conclusions are in §3 and the four decisions in §4.
