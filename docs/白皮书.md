# 恒晷 Aevum Studio 算法白皮书

**中文** · [English](白皮书.en.md)

## 1. 这份文档解决什么问题、写给谁

`docs/system_design.md` 讲模块结构与功能清单，README 讲功能与用法；这份文档只讲一件事：
**每个算法的口径**——公式、常量、取值依据、边界与已知上限。写给两种人：要改算法的新接手者，
以及若干个月后忘了「这个数为什么是 0.40」的自己。

口径约定：

- 每个数字都能指到出处：`crates/aevum-core/src/xxx.rs::符号`，或遗留台账的编号（A1–A9、B2–B5）。
  指不到出处的数字一律不写。
- 「判据」指 `crates/aevum-core/tests/suite/` 下或模块 `#[cfg(test)]` 里的测试名；
  判据存在意味着这个数被钉住了，改它必须同时改判据并能说明为什么。
- 本文档不与金标机制重复论证。金标（Python oracle）只证明 Rust == Python；
  **它不能证明一个数字是对的**——两端写同一个猜值金标永远绿。参数正确性由第 8 节的
  自证式测量负责，两者分工不同。

## 2. 数据流与单一事实源

### 2.1 总链路

```
序列发现 (sequence) → 逐帧测光 (metrics / deflicker) → 曝光修正 Ev → 显影主链 (develop)
→ 预览 / 静帧导出 / 成片导出 (preview / export) → 编码 (ffmpeg 或内置写盘)
```

### 2.2 两套测光口径，各自独立

- `crates/aevum-core/src/metrics.rs::FrameMetrics`：gamma 域平均亮度（「看起来多亮」），
  512 长边、区域平均，供胶片条曲线、序列 QA、曝光台阶用。
- `crates/aevum-core/src/deflicker.rs::FrameMeans`：**线性光** 1%~99% 截尾均值
  （`deflicker.rs::trimmed_mean`），长边 320（`deflicker.rs::SCAN_LONG`）。
  去闪必须在线性域做：sRGB 编码会压扁明暗跳，且压不住彩色闪烁。

两套互不调用、互不混用。这是有意的冗余：一个服务「显示」，一个服务「校正」。

### 2.3 显影主链是唯一的像素真相源

GUI 预览、静帧导出、视频导出全部经过 `crates/aevum-core/src/develop.rs::render`；
预览层的 `crates/aevum-core/src/preview.rs::render` / `::render_sketch` / `::render_hdr`
只是给 `develop::render` 换 `Opts` 的转发。几何（旋转/位移/取景）在
`crates/aevum-core/src/warp.rs`，预览与导出走同一个函数。不存在第二套像素实现——
这是「预览即成片」能成立的唯一方式，也是金标能一次钉住全部三条路的条件。

`develop.rs::Opts` 的四个开关决定跳过什么：

| 开关 | 跳过 | 用途 |
|---|---|---|
| `sketch` | 降噪、锐化、清晰度、纹理、局部空间项 | 拖动中保跟手 |
| `for_lut` | 镜头校正、全部空间运算、蒙版、颗粒、晕影 | 生成 .cube（只有逐点项能进 LUT） |
| `local` | 单色与全局专属项 | 蒙版内部的子链 |
| `hdr` | 只改一处：终点不把 >1 钳到 1 | HDR 导出 |

`sketch` 与全量的差异**恰好是**被跳过的那几项，无空间参数时逐点一致
（`preview.rs::render_sketch` 注释）。

### 2.4 `STAGES_READY`：诚实开关

`crates/aevum-core/src/develop.rs::STAGES_READY` 列出已落地且被金标逐像素钉住的阶段
（`tone` / `lut` / `spatial` / `vignette` / `mask` / `mask_local` / `grain`）。
`tests/suite/develop_golden.rs` 只对「所有涉及阶段都在表内」的 case 做逐像素断言。
实现新阶段就加进去；没实现就别声称一致。

### 2.5 去闪烁修正的形状

`crates/aevum-core/src/develop.rs::Ev`：整帧 EV 偏移 `add` 加三个通道残差 `chan`。
分通道去闪时，三通道均值并进 `add`、只把色差留在 `chan`，两者相加精确还原该通道偏移
（`deflicker.rs::Analysis::chan_residual_per_frame`，判据
`channel_residual_reconstructs_the_offset`）；`chan` 全零时与只补亮度的老口径逐位一致。

## 3. 显影主链逐阶段

以下顺序照抄 `crates/aevum-core/src/develop.rs` 顶部注释，与 Python oracle
`acceptance/reference/grade.py::_core` / `apply` 严格一致。所有像素缓冲是 sRGB 编码、
行优先、`[0,1]` 的 f32；亮度系数 `LUMA = [0.2126, 0.7152, 0.0722]`
（`develop.rs::LUMA`）。逐像素段并行用 `MIN_PIXELS = 4096` 分档
（`develop.rs::MIN_PIXELS`），分线程不改任何数值。

### 3.0 镜头校正（链首）

`crates/aevum-core/src/develop.rs::render`：LCP 配置文件（EXIF 匹配，`lcp.rs::Correction`）
优先，其次机型镜头库（`lensdb.rs`），最后手动三项（畸变/暗角/紫边，
`develop/spatial.rs::lens`）。顺序有含义：先修真实几何，手动滑杆才是创作量。
`for_lut` 跳过整段。

### 3.1 外部 .cube 外观

主链之前套一层三维查表（`crates/aevum-core/src/cube.rs`）。放在这个位置与「外观改的是
输入而非输出」的用法一致。Python oracle 没有这一步，金标 case 里 `look_cube` 恒为空，
不影响比对。LUT 导出走 `for_lut` 逐点链（`cube.rs::build`），格点红分量变化最快
（`cube.rs::lattice`），默认 65³（`cube.rs::DEFAULT_SIZE`）。

### 3.2 降噪

AI 降噪在前、经典引导滤波降噪在后（`develop.rs::core`）：AI 网学的是原样噪点，
先跑完残噪再交给引导滤波。两者都在 `opts.detail()` 内（草图/局部跳过），
参数为 0 整段跳过，金标不受影响。

AI 网络结构与实测见 `crates/aevum-core/src/ai_denoise.rs`：亮度、色度两路各自是
4 层 3×3 卷积残差网；亮度输入 Rec.601 亮度，色度输入 `(B−Y, R−Y)`——有符号色差在灰上
恒为 0，色度降噪不会拖偏颜色。合训失败过（5000 轮色度 PSNR 仍 0.00 dB），所以分训。
推理按 256² 分块、只取中心、重叠区 4 像素（`ai_denoise.rs::TILE` / `::RADIUS`）；
x86_64 有 AVX2+FMA 走手写向量路径，5984×3959 单帧两路合计约 2.3 秒
（1600×1067 预览约 0.2 秒），标量路径单网约 5.7 秒。

手动噪声 σ 的映射 `σ = 0.002 + (v/100)^1.6·0.030`（`grade.rs::nr_sigma_manual` 注释）
是 A9 的产物，见第 8 节。

### 3.3 白平衡 / 曝光（线性域，一次完成）

`develop.rs::core`。增益 `g = [1+0.30t+0.08u, 1−0.22u, 1−0.30t+0.08u]`
（t = temperature/100，u = tint/100），按 `LUMA` 加权归一化后乘 `2^shift`
（shift = 参数曝光 + 去闪 EV，分通道时含残差）。sRGB↔线性往返用
`develop.rs::srgb_to_lin` / `::lin_to_srgb`。

**曝光高光肩部**（`hl_rolloff`，对齐 LR rolloff 口径）：`yy = y + krl·t/(1+t/len)`，
`t = max(0, y−knee)`，按亮度比值缩放以保色相。两点被测钉住（A7）：

- `knee = 0.75`（线性）= 编码 0.881：低于它的像素逐位不动，实测编码 0.875 不动、
  0.885 开始动，窗口只有 0.01 编码；
- `len = 0.40`：饱和抬升量 = `krl·len`，拉满时编码 1.0 抬到 [1.03, 1.10]。

**注意这个函数不是 C1 连续**：knee 处斜率从 1 跳到 `1+krl`，是 C0 折点。这是有意保留
（只抬最亮的一小撮），`develop.rs::core` 注释里明确写了它曾经被错写成「C1 连续」，
别改回去。

### 3.4 对比度

gamma 域增量与线性光域 S 曲线增量按 `contrast_linear` 混合
（`develop.rs::core`）。线性域 S 曲线是 `develop.rs::contrast_s_lin`：绕**中灰**转
（`u = xl^0.4496` → smoothstep → `u^2.2242` 拉回），常量 `GAMMA=0.4496` /
`INV_GAMMA=2.2242` 写死在函数里。直接对线性值做 smoothstep 会把支点抬到编码 0.735，
实测 contrast=50 时中灰 0.5 被压到 0.4487（8 位吃掉 14 级）；现在的实现中灰全档不动
（判据 `fit_sliders.rs::contrast_linear_keeps_mid_gray_fixed`，台账「已关闭」表）。

### 3.5 去朦胧（逐点项 + DCP 空间项）

逐点项在 `develop.rs::core`：正 `dz>0` 时 `x ↦ (x−v)/(1−v)`，`v = dz·0.25`；
负值时 `x ↦ x(1−0.20v)+0.07v`。

空间项是暗通道先验去雾（He DCP + 引导滤波精修），`develop/dehaze.rs::dehaze_dcp`，
线性域执行，叠在逐点项之后。七个内部常量集中在 `dehaze.rs::DehazeTune`，
每个都有出处（A1–A4，见第 8 节）：`t0=0.1` 与 `ω=0.95` 是 DCP 原文值，
`ε=1e-4` 是引导滤波在 [0,1] 值域的惯例（0.01²），`r_div=200`、`round_div=1`
（有效半径 = 名义半径，判据 `min_filter_effective_radius_is_the_nominal_radius`）、
`t_radius_mul=4`、`contrast_amp=0.15`。对比微调幅度 = contrast·0.15，
判据 `contrast_trim_is_linear_and_safe`（拉满黑位位移 3.1%，10% 线以内）。

已知上限：DCP 在天空上必然压暗（天空没有暗通道），这是算法上限不是参数错；
扫参同时用恢复 PSNR 与透射 RMSE 两把尺就是为了把两者分开
（`dehaze.rs` fit 模块 `score` 注释）。金标 48×64 只覆盖引导滤波全分辨率分支，
下采样分支由 `dehaze_downsample_matches_python` 以 Python 参考统计量（容差 2e-3）覆盖，
不逐像素冻结。

### 3.6 高光 / 阴影 / 白色 / 黑色

按 `LUMA` 亮度权重一次扫描完成（`develop.rs::core`）：

- 高光：`fac ×= 1 + a·0.5·smooth(0.45, 1.0, lum)`
- 阴影：`k = sh·0.45·smooth(0.55, 0.0, lum)`，`fac ×= 1−k`，`add` 混向 1.2
- 白色：`k = wh·0.5·smooth(0.60, 1.0, lum)²`
- 黑色：`add += bl·0.35·smooth(0.40, 0.0, lum)²`

段末默认硬钳 [0,4]；`black_soft`/`white_soft` > 0 时换成抛物线软拐点
`develop.rs::soft_clip_high` / `::soft_clip_low`（C1 连续、恒 ≤1、单调不减，可证明）。
宽度映射 `s = 0.08 + 0.17·(v/100)`（A6）：上端 0.25 保住编码 0.75 以下逐位不动，
下端 0.08 保证最小档仍有约 0.7 级的可见作用。判据
`fit_sliders.rs::soft_clip_is_c1_and_width_bounds_are_meaningful`。

### 3.7 锐化

USM + 边缘蒙版 + halo 限制（`develop/spatial.rs::sharpen`，`opts.detail()` 内）。
恒开的边缘保护 `sharp_protect`（对齐 LR Sharpen3）已实测：全量锐化无保护把噪声放大
1.944×，20 压到 1.773、100 压到 1.093，边缘增益全程不动（1.359）
（`fit_sharpen_protect.rs`，`grade.rs::sharp_protect` 注释）。`sharp_masking`
的 0–50 死区已消（噪声增益 25→1.816、50→1.385，判据
`fit_sharpen_protect.rs::masking_responds_across_the_whole_slider`）。

### 3.8 清晰度 / 纹理

共用 `develop/spatial.rs::local_contrast`：亮度场引导滤波取 detail，中间调权重
`0.35 + 0.65·mid`，比值钳 [0,3]。清晰度半径 `max(2, min(w,h)/60)`、量乘 1.6、
ε=0.02（`develop.rs::clarity_radius` 与 `core` 调用点）；纹理半径
`max(1, min(w,h)/300)`、ε=0.004（`develop.rs::texture_radius`）。两个半径公式照抄
Python。草图跳过（全链最贵项之一）。

### 3.9 自然饱和度 / 饱和度

`develop.rs::core`：`f = 1 + sat`；vibrance 再乘 `1 + vib·(1−range)·1.3`
（range 为通道极差，低饱和像素提得多）。按「相对亮度放大」计算，HDR 模式下超白部分
参与（否则 HDR 高光被这一站拍平）。HDR 只压负值、SDR 钳 [0,1]。

### 3.10 色彩分级

`develop/lut.rs::color_grade` + `::grade_table`：亮度 1024 级（`GRADE_N`）的
RGB 偏移表。三段权重窗由均衡 `a = 0.46 − balance/100·0.12`（钳 [0.18, 0.78]）控制；
染色强度 = s/100·0.18 乘零和色相向量（`lut.rs::hue_vec`），明度偏移 = l/100·0.15；
混合 blending 把权重向纯明度插值。逐点查表，无邻域访问，`for_lut`/sketch 照跑。

### 3.11 HSL

`develop/lut.rs::hsl` + `::hsl_tables`：8 条色相带中心
`HSL_CENTERS = [0,30,60,120,180,240,285,330]`，色相权重
`smooth(50, 18, hue_dist)` 落在 65536 级色相表（`HUE_BINS`）上。
色相偏移 = h/100·40 度，饱和系数 = 1 + s/100·w，明度系数 = 1 + l/100·0.6·w。
三轴共用**原始色相**的分箱索引（Python 先算 idx 再改 h）。RGB↔HSV 按 OpenCV
float 约定（`lut.rs::rgb_to_hsv` / `::hsv_to_rgb`，往返稳定性有判据
`hsv_round_trip_is_stable`）。

### 3.12 单色

`develop/lut.rs::mono`：Rec.709 亮度与 8 色相带亮度混合表（Lightroom B&W Mixer 口径），
按 `mono/100` 与原色插值。蒙版局部链（`opts.local`）跳过——单色是全局专属项。
注意：黑白必须走 mono，只压 saturation 会让混合面板 8 条推子全程无效
（`grade.rs::preset("黑白对比")` 注释）。

### 3.13 色阶 + 参数曲线 + 曲线（合成一张表）

`develop/lut.rs::curve_lut`：色阶五项（`::levels_lut`，黑白场下界 `+2/255` 的最小跨度、
gamma 钳 [0.1, 5.0]）与参数曲线四段（`::par_lut`，幅度 `PAR_SCALE = 0.18`、
`np.maximum.accumulate` 保证严格不减）先复合成基索引，再过主曲线与分通道曲线
（Fritsch–Carlson 单调三次插值，`grade.rs::pchip_lut`），合成 65536 级 uint16 表
（`CURVE_N`）一次查完。量化口径 `np.rint`（半数取偶）由 `lut.rs::rint` 复现。

**曲线 HDR 尾部**（`lut.rs::tone_curve_keep_over`，HDR 专用）：x>1 的输入按
`y1 + (x−1)·slope` 延伸而非截断，`slope = pchip_end_slope/255 + k·0.6`。
0.6 这个数是 A5 的产物：判据四条（接得上 / 不放大 / 斜率落 [0.40, 0.85] /
x=4 与 x=2 分得开），实测 slope = 0.6033，x=1.5 → 1.0858、x=2 → 1.3873、
x=4 → 2.5934（s_curve(200) 端点 0.7843）。它吃的是曝光段造出的 >1
（`grade.rs::curve_hdr_tail` 注释）：镜头段的 clamp 在曝光之前，碰不到它。

### 3.14 局部蒙版

`crates/aevum-core/src/mask.rs`：几何用归一化坐标存盘，任意预览分辨率圈住同一块地方；
参数是**相对全局的增量**。渲染（`develop.rs::render`）：留一份原图 → 全局主链跑完 →
对每个有增量的蒙版，拿原图叠增量重跑 `develop.rs::core`（`opts.local`）→
按权重场混回 → 按模式收口（SDR 钳白 / HDR 压负）→ 最后补一遍蒙版内的
锐化/降噪/清晰度/纹理（`develop/spatial.rs::mask_spatial`，Python 同口径）。
蒙版可携带的逐点参数 13 个（`mask.rs::MASK_KEYS`），与 Python `MASK_KEYS` 一一对应。

### 3.15 颗粒

`develop/spatial.rs::grain`（`for_lut` 跳过）。亮度调制 `grain_lum` 是设计选择不是拟合：
拉满时暗部 ×2.5、高光 ×0.3（半档 ×1.75 / ×0.65），跨实现一致性由金标
`grain_stats_lum` 保证——只比统计量，容差 ±25%（`grade.rs::grain_lum` 注释）。
颗粒随机序列与 numpy 不可能相同（各自的确定性发生器），所以金标只钉统计量与空间结构，
场按 (尺寸, size, freq) 缓存、与帧号无关。

### 3.16 晕影

`grade.rs::vignette_mask`：乘法蒙版，椭圆/圆形半径按 `roundness` 插值，
`start = midpoint·0.9`、`width = max(0.05, feather·1.2)`。高光保护
`vig_hl_contrast` 按当前像素亮度把亮部被压掉的量还回去（亮于 0.5 才起作用）。
排在蒙版与颗粒之后：局部提亮不该把压暗的四角拉回来（`develop.rs::render` 注释）。

### 3.17 终点收口

`develop.rs::render` 最后一步：SDR 钳 [0,1]（下游按 8bit 写盘），HDR 只压负值——
白以上必须留给 PQ 编码。这是 HDR 与 SDR 唯一的实质差别，三处 clamp
（晕影前蒙版混合口、vibrance 口、终点）都由 `opts.hdr` 分流。
判据 `fit_sliders.rs::hdr_render_keeps_brightness_above_white`
（SDR 顶 1.0 / HDR > 1.2），SDR 金标 md5 未变（台账「已关闭」表）。

## 4. 序列级算法

### 4.1 对齐

`crates/aevum-core/src/align.rs`。两种估计器：`Template`（底部模板 + CLAHE 灰度 +
归一化互相关 + 抛物线亚像素，对相机下坠的垂直漂移最稳）与 `Phase`（相位相关，
同一套自写 2D FFT）。约定 `dst(x,y) = src(x−off_x, y−off_y)`，与 Python
`acceptance/reference/align.py` 一致。模板区起点 0.7、搜索边距 150 px、
CLAHE 网格 8 / 裁剪 2.0（`align.rs::SEARCH_MARGIN` / `::TEMPLATE_START` / `::CLAHE_*`）；
默认参数 `max_shift=64`、`smooth_window=15`、`jump_px=24.0`、`min_score=0.35`
（`align.rs::AlignOptions::default`）。4K 模板的互相关用自写 FFT，只覆盖搜索窗
（4096×2048），不留整帧 f32 副本。残差复核按底部 ROI 双线性 warp 逐像素算，
不物化整幅 warp。金标：`tests/suite/align_golden.rs`。

### 4.2 去闪烁

`crates/aevum-core/src/deflicker.rs`。测光（线性光截尾均值，2.2 节）→ log2 →
逐列：中值滤波（边界复制）压单帧跳变 → 高斯平滑（σ = max(0.8, window/4)，
`deflicker.rs::analyze`）避免校正引入台阶 → 偏移 = 目标 − 当前，按 strength/100
施加并钳 ±`MAX_EV`（3.0，`deflicker.rs::MAX_EV`——再大就不是闪烁而是坏帧）。
多尺度模式先过窗 3 再过全窗（`deflicker.rs::pass_windows`）。窗口钳 [3, 199]
（`deflicker.rs::WINDOW_MIN` / `::WINDOW_MAX`），偶数窗口进一，超过帧数收拢。
读不出的帧线性插值补洞但偏移置 0（判据 `missing_frames_are_interpolated_and_left_alone`）。
统计量：相邻帧差 P95（`deflicker.rs::jitter`）。金标
`acceptance/oracle/golden/deflicker.json`，容差 1e-4。

### 4.3 HDR 合并

`crates/aevum-core/src/hdr.rs`：Mertens 曝光融合，不做相机响应标定、不还原辐射度。
每像素按「曝光好 × 饱和 × 对比」三个公开公式打分，拉普拉斯金字塔逐层加权塌缩。
一次最多 9 张（`hdr.rs::MAX_FRAMES`）。

### 4.4 重定时（变速 + 运动模糊）

`crates/aevum-core/src/retime.rs`。速度键用**源进度**（0..1）而不是输出秒——成片时长
是速度的积分结果，不是输入。输出帧数 `n_out = ⌊n_src·∫₀¹ du/speed(u)⌋`，常速时
恰为 `n_src`。快门 `shutter`（0..1）：输出帧曝光区间内跨过的源帧按重叠时长加权平均
——延时圈的 accumulate-and-average，不靠光流补帧；0 = 只做相邻两帧线性插值。
单次输出帧数上限 200,000（`retime.rs::MAX_OUTPUT_FRAMES`，超限当场拒绝——慢放拉太长
等于倍速填错）。`enabled=false` 或常速零快门走 1:1 快路，一个像素不动
（`retime.rs::Retime::is_identity`）。

### 4.5 配乐混流

`crates/aevum-core/src/audio.rs`。序列没有原声，配乐是**替换式**的，不做双路混合。
延迟用 ffmpeg `adelay` 补真静音采样，循环用 `-stream_loop`，淡入淡出与音量走滤镜
（口径对齐 Python `acceptance/reference/audio.py`）。容器能原样放的编码只有
aac / mp3 / alac（`audio.rs::COPYABLE`），其余转 AAC；音量偏差 ≤0.5% 内不重编
（`audio.rs::AudioOptions::needs_filter`）。

## 5. RAW 解码：能力边界

`crates/aevum-core/src/raw/mod.rs` 是「通用兜底：CFA + 内嵌预览」的双路径设计，
两条路都必须如实报告走了哪条（`raw/mod.rs::RawPath`）：`Sensor`（16 位传感器直解）
或 `Preview`（机身完整 JPEG）。保真度由 `RawPath` 表达，不由位深冒充——预览本身 8 位，
返回时按 `v·257` 顶到 16 位，**这只是位宽表示，不新增精度**。

### 5.1 内置 CFA 路径（解什么、拒什么）

只在 IFD 自己说得清楚时才解：单通道 CFA 或线性原始数据、不压缩（DNG 另认
Adobe Deflate，`dng.rs`）、8 或 16 位容器、条带长度能按行整除。上限：
文件 512 MB、像素 40 MP（`raw/mod.rs::MAX_FILE_BYTES` / `::MAX_PIXELS`）；
DNG 路径 24 MP（`dng.rs::MAX_PIXELS`）。

**绝不猜像素**是整条路径的原则。以下情况按软错处理——退内嵌预览，而不是猜：
12/14 位行内打包（「每行打包」与「整图连续打包」在常见宽度下条带总字节数完全相同，
猜错 = 整幅横向错位）、无损 JPEG、CRX、瓦片存储、私有 CFA 位置标记。
CFA 只认标准标记 `CFARepeatPatternDim`(33421) / `CFAPattern`(33422)；
白平衡只用 `AsShotNeutral`(50728) 三通道增益，缺标记就不调色。

以下按硬错处理——给具名错误，不退不猜：BigTIFF/RRIF 容器、CR3 找不到内嵌预览
（CR3 不是 TIFF，是 ISO base media 容器 + 佳能 CRX，内置路径**不解 CRX**，
只做「在容器字节里找机身完整 JPEG 预览」一件事）、文件或像素数超上限。
边界判据见 `tests/suite/raw_reads.rs`、`tests/suite/dng_reads.rs`。

内置去马赛克两种方法：`cell_average`（2×2 单元平均，与 `dng.rs` 刻意同一套粗估器）
与 `directional`，运行时可切（`raw/mod.rs::demosaic_method` / `::set_demosaic_method`）。
内置路径**不做** ColorMatrix/相机色域/预设基线——需要色彩矩阵才正确的 C/M/Y 图案、
四色拜尔与 X-Trans 在上层被拒、走预览。

### 5.2 rawler 回退

默认 feature（`raw-rawler`）下 `read` 先试 rawler 传感器直解：CRX、12/14 位打包这些
内置拒绝的布局由它补齐成 `Sensor` 路径；解不动再退内置双路径。
`--no-default-features` 编译时行为与 v0.3.0 完全一致。rawler 是 LGPL-2.1 静态链接，
需要完全不含 copyleft 的构建就用 `--no-default-features`（README「许可」节）。

### 5.3 真实样本钉住的四个 bug（B5）

合成靶测不出、被真实样本 `samples/cc0/apple-iphone6s-plus/IMG_0853.DNG`
（CC0，4032×3024）暴露并修掉：①真实 iPhone DNG 打不开（内置解析失败后不回退）；
②只读 IFD0 拿到 852×640 缩略图（主图在 SubIFDs，`dng.rs::TAG_SUB_IFDS`）；
③元数据与像素存储耦合（compression=7 时连尺寸都报不出）；④**CFA 取值映射整体偏移
一位**（规范 `0=R,1=G,2=B`，代码按 2/3/4 读，合规文件全被拒，而合成靶按同一个错误
约定写 → 自我印证的假绿）。判据 `tests/suite/raw_real_sample.rs` 四条；两个变异
（CFA 映射改回 2/3/4、`main_ifd` 退化成 IFD0）都报红。

### 5.4 去马赛克的采样决定上限（B4）

45° 斜边的绿误差顶在「边界占比 × 整步」上：R/B 位的绿邻居只有上下左右，45° 线上是
同色 R/B 不是 G，边界那一圈必然整步错。1/6 × 13000 = 2167，实测 R/B 位平均误差
2190 = 0.168 × 步长，两者对得上——除边界外一个像素都没错。方向法的 +3 dB 来自
R/B 通道（色差恒定），不是绿；软判决已否掉（同一张靶 45° 24.55 → 23.85 dB、
彩色边 19.81 → 17.23 dB，把候选混成中间值等于抹平边缘）。判据
`raw::cfa::tests::diagonal_edges_are_bounded_by_the_sampling_pattern`。

## 6. 色彩

### 6.1 工作空间

调色链路全程按 **sRGB（D65 白点、sRGB 传递函数）** 算。线性/编码往返只有
`develop.rs::srgb_to_lin` / `::lin_to_srgb` 一对函数。去雾、白平衡、曝光在展开后的
线性光里做；查表类运算在编码域做。不存在第二个工作空间。

### 6.2 输出标记与转换

`crates/aevum-core/src/colorspace.rs`，两条线各管一件事（**只改标记不搬像素是错的**）：

- `Srgb`：默认，不嵌 ICC、不改像素。
- `DisplayP3`：DCI-P3 原色 + D65 + sRGB 传递函数；像素真转换到 P3，静帧嵌自生成
  ICC（Bradford 自适应到 D50 PCS——规范要求，少它系统读出偏色的白）。
- `Rec2020`：BT.2020 原色 + D65 + γ2.4，**SDR 标记，不是 HDR**。

ICC 常数全部是公开色度学标准值加自推矩阵，不引用第三方色彩引擎。ICC 字节的最终裁判
不在单测：设 `AEVUM_ICC_DUMP=<目录>` 落盘后用 `python acceptance/oracle/check_icc.py`
让 littleCMS 读回核（两次曲线形状改版都出自那一步）。

### 6.3 DCP 相机配置

`crates/aevum-core/src/dcp.rs::decode`：白平衡 → 颜色矩阵 → HueSatMap（ProPhoto 线性
RGB 的 HSV 三线性插值，DNG 1.6 第 6 章口径）→ 曝光偏移 → Look 表 → 色调曲线。
双光源配置按 `AsShotNeutral` 在两组标定白点间插值；机型不匹配直接拒绝。
DCP 矩阵定义在相机线性 RGB 上，所以只有 DNG / 厂商 RAW 能接，JPEG/内嵌预览直接报错。
厂商 RAW 已在传感器空间做过白平衡增益，不能做第二次——RAW 只套矩阵。

**有意的口径偏差**：`ProfileToneCurve` 规范放在 ProPhoto 流水线里，本版套在线性 sRGB 域
——逐通道曲线在两种线性域只差饱和色的通道比例，沿用既有口径以保持已导出色彩不变
（`dcp.rs` 模块头明文记录）。

### 6.4 LCP 镜头配置

`crates/aevum-core/src/lcp.rs`：只管几何（畸变/横向色差/暗角），不管颜色。
数据形状来自 Adobe Camera Raw 自带的 3633 份在野样本；分段暗角表（551/3633 份有）
比多项式更贴厂商实测（|差| 中位 0.0045、最大 0.13），表覆盖到画幅角时优先，
退化平表（85 帧）与只管一小段半径的表（7 帧）退回多项式。选帧按对数焦距插值。

### 6.5 HDR 与 PQ

`crates/aevum-core/src/hdr_output.rs`：渲染输出（sRGB 编码值，可 >1）→
`srgb_to_linear_ext`（幂段对 x>1 连续延伸）→ ×参考白得 nits → PQ 反编 → 10-bit
full-range 码值。三件事钉死：

1. **参考白 = 203 cd/m²**（`hdr_output.rs::REFERENCE_WHITE_NITS`，BT.2408）。
   按 100 nits 映射会让 HDR 版比旁边的 SDR 窗口暗一档；203 让两者并排亮度一致、
   只有高光往上走。
2. **不做色调映射滚降**。PQ 能表达到 10,000 nits（`hdr_output.rs::PQ_PEAK_NITS`），
   把 >1 沿曲线尾部送进去正是这条链存在的理由；自制滚降等于替用户决定高光压多少，
   还会抹掉 `curve_hdr_tail` 的效果。峰值由显示器决定。
3. **full range**（`-color_range pc`），不是视频的 64–940 limited range。实测同一份
   10-bit 源 limited 往返最大差 178/65535、full 是 128/65535。

PQ 正反式内部走 f64（`hdr_output.rs::nits_to_pq` / `::pq_to_nits`）：f32 在 `Y^m1`
段的舍入会在 10-bit 端点抖出 1 级。

## 7. 导出

### 7.1 与预览同一条链

静帧与成片的像素口径就是 `preview::render`（`Opts::FULL`），空间项与局部蒙版一项不少；
默认参数下与 Python oracle 逐像素一致（`export.rs` 模块头）。几何（拉直/对齐位移/
裁切/取景）在 `warp.rs`，预览与导出走同一个函数。输出锐化作用在**缩放之后**的那帧上。

### 7.2 静帧容器与约束

`export.rs::StillFormat`：

| 格式 | 位深 | 有损 | 能否当视频中间帧 | EXIF |
|---|---|---|---|---|
| PNG 8bit (`Png8`) | 8 | 否 | ✅ | ✅ |
| TIFF 16bit (`Tiff16`) | 16 | 否 | ✅ | ❌（IFD 偏移指向整文件，搬不进去） |
| JPEG | 8 | 是（quality 1..100） | ❌ | ✅ |
| WebP | 8 | 否（`image` 只有 VP8L 无损档，quality 无效） | ❌ | ✅ |
| AVIF | 8/10 跟动态范围 | 是（libaom-av1，quality→crf） | ❌ | ❌（mov muxer 不写 EXIF item） |

JPEG/WebP 只给静帧：视频中间帧要么 8bit 无损要么 16bit，塞一层有损容器等于压两遍
（`export.rs::StillFormat::frames_ok`）。AVIF 是唯一装得下 HDR（PQ）的静帧容器：
SDR 8bit `yuv444p`、HDR 10bit `yuv444p10le` + full range；色域用 nclx 标记，不嵌 ICC。
判据 `tests/suite/export_hdr.rs::pq_codes_are_actually_written_into_the_file`。

### 7.3 HDR 静帧的容器拒绝（B3）

TIFF/PNG 声明 PQ 只能靠 ICC `curveType` 的 4096 点采样表，主流读图器不解析，读出来
一片灰；改成线性 16bit 则与 Photoshop 默认按 gamma 解释 16bit TIFF 的行为冲突。
所以 HDR 静帧**只走 AVIF + Rec.2020**，其余容器当场拒绝并说清：
`export_hdr::hdr_pq_is_refused_by_eight_bit_containers`、
`::hdr_pq_is_refused_by_narrow_gamuts`；面板侧补齐与强制的判据在
`crates/aevum-ui/src/state.rs::hdr_forces_rec2020_and_avif`。

### 7.4 成片

编码走外部 ffmpeg：H.264 8bit / H.265 10bit（`export.rs::Codec`）。HDR 成片（B2）
只能 H.265 且必须 Rec.2020：`pipe_command` 按动态范围在 `rgb24`/`rgb48le` 之间切
`-pix_fmt`，x265 VUI 写 `bt2020`/`smpte2084`/`bt2020nc`；PNG 序列那条路直接拒绝
（PNG 无处声明 PQ）。判据 `tests/suite/export_video.rs::hdr_video_is_really_ten_bit_pq_in_the_bitstream`
（真编一段读回流信息）、`::hdr_video_refuses_h264_and_narrow_gamut`、
`export::tests::pipe_bytes_per_pixel_match_the_declared_pix_fmt`（3 vs 6 字节/像素）。

### 7.5 输出锐化阶梯（A8）

`export.rs::OutputSharpen::profile`，作用在缩放后的帧，用途档定三元组、强度档只乘
amount（Low/Standard/High = ×0.7/1.0/1.4，`export.rs::SharpenStrength::scale`）：

| 用途 | amount | radius | thr | MTF50× | halo |
|---|---|---|---|---|---|
| 屏幕 screen | 0.55 | 0.6 | 0.004 | 1.096 | 0.19% |
| 光面 glossy | 0.80 | 0.9 | 0.003 | 1.161 | 0.71% |
| 哑面 matte | 1.00 | 1.4 | 0.002 | 1.209 | 2.09% |

三格必须同向（amount↑ radius↑ thr↓）；九个真实组合 halo 全 < 3%，最紧的哑面+高
2.93% 只剩 0.07 个百分点余量，那两格不能再加。判据
`fit_sharpen.rs::purpose_profiles_form_a_measured_ladder`。

## 8. 参数拟合方法论

### 8.1 两条路

`TODO(fit)` 的意思是「这个数字没有依据」。消掉它只有两条路
（`docs/遗留台账.md` A 组序言）：

1. **文献值**：原论文/规范里写着这个数，标注出处；
2. **自证式测量**：构造已知正确答案的场景，测「参数 → 可观测物理量」的映射。

判据必须**不依赖参考实现**——金标只证明 Rust == Python，猜值写进两端就永远绿。
自证靶的典型：去雾用大气散射模型 `I = J·t + A·(1−t)` 从已知无雾场景造雾图
（`dehaze.rs` fit 模块 `truth_pair`），量恢复 PSNR 与透射 RMSE；去马赛克用已知答案的
合成靶量方向误差。靶本身的坑也记录在案：透射场若全图平滑，扫参会偏向「半径越大越好」，
量出来的是靶不是算法——所以块间距离必须突跳，且必须含天空块（否则大气光低估 21%，
盖过参数间一切差别）。

### 8.2 A1–A9 摘要表

| # | 常量 | 现值 | 依据 | 判据 |
|---|---|---|---|---|

### 8.3 方法论上的教训（已写进判据结构）

- **判据必须贴着被钉的对象**。去雾 fit 第一版五条负向验证全绿——因为它们只测
  「0.95 比 0.85 好」，把默认值改成 0.85 依然绿。正确写法是拿 `DehazeTune::default()`
  本身当被测对象（`dehaze.rs` fit `default_tune_matches_the_documented_values` 注释）。
- **容差别盖住差别**。引导半径倍数在 480×360 上 4 与 8 只差万分之几，相对容差一放
  「默认值被改到 8」就漏过；判据改成「默认值必须是全表最优平台」且分辨率的选取要
  让差别可测（`guided_radius_multiple_sits_on_a_plateau` 注释）。
- **「默认值落在最优平台」比「默认值等于最小值」诚实**。0.09296 vs 0.09285（0.1%）
  属于同一平台，硬要求相等只会逼人改常量。

## 9. 已知上限与明确不做

1. **HDR 预览不做屏模拟（B1，判据改写）**。SDR 面板峰值就是白，203 nit 参考白与
   1000 nit 峰值的差别是显示器亮度的事，软件改不了；硬做只能靠假色调映射，等于替用户
   决定高光压多少。改成能做且有用的一件事：白以上折进最后 10% 码值检视有没有层次
   （`preview.rs::FOLD_KNEE = 0.90`、`::FOLD_SOFTNESS = 1.0`——1.0 由输出端分辨力定：
   实测 x=2 落 0.9667、x=4 落 0.9955，软度 0.25 时 x=2 已 0.9988，白以上又变一片白）。
   白以下逐位不动。判据 `fold_leaves_everything_below_the_knee_alone` 等（preview.rs）。
2. **TIFF/PNG 16bit HDR 不做（B3）**，理由见 7.3；交付走 EXR/DNG 的定位、TIFF 在专业
   链条里是过完色的 SDR 底片。
3. **去马赛克 45° 上限是采样决定的（B4）**，不是调参问题，见 5.4。
4. **内置 RAW 路径不解 CRX、不做色彩矩阵、不碰私有标记**（5.1）——补齐靠 rawler，
   不是往内置路径里塞猜测。
5. **DCP `ProfileToneCurve` 在线性 sRGB 域执行**（偏离规范的既定口径，6.3）。
6. **颗粒随机序列不与 numpy 对齐**：只钉统计量与空间结构（金标 ±25%）。
7. **AI 降噪的可用性以 AVX2+FMA 为前提**：标量路径单网约 5.7 秒（`ai_denoise.rs`）。
8. **重定时不用光流补帧**：快门加权平均是口径，光流是另一个算法档位。
9. **HDR 输出不加色调映射滚降**（6.5 第 2 条）。
10. **硬上限**（都是显式拒绝而不是静默裁剪）：RAW 文件 512 MB / 40 MP（DNG 24 MP）、
    HDR 合并 9 张、重定时输出 200,000 帧、去闪窗口 3..199 帧、单帧修正 ±3.0 EV。
11. **金标覆盖的分支边界**：引导滤波下采样分支无逐像素金标，只有 Python 参考统计量
    （`develop/spatial.rs::guided` 注释）；颗粒只比统计量。这两处是已知的、
    已声明的覆盖缺口，不是遗漏。

## 10. 如何验证

### 10.1 五关门槛

`acceptance/check.sh`（提交门槛，一红全停）：

0. 版本与文档一致性：Cargo.toml 真源 → lock/README/CHANGELOG；中英孪生文档互链；
   代码模块级与 pub 项注释双语（`acceptance/check_version.py`、`check_docs.py`、
   `tools/doc_lint.py`）。
1. `cargo fmt --check`。
2. `cargo clippy --workspace --all-targets -- -D warnings`。
3. 全量测试（`cargo test --workspace`）：没有 ffmpeg 时导出类用例**报红不跳过**
   （历史上 12 个用例静默跳过导致 AVIF 导出坏了一整轮没人知道）。
4. 界面布局自检：`aevum.exe --selftest`（无显示器）。

### 10.2 金标

- Python 参考实现 `acceptance/reference/`（不参与构建、不随包分发，exe 里没有 Python）；
  冻结金标在 `acceptance/oracle/golden/`，重冻结用
  `./.venv/Scripts/python.exe acceptance/oracle/freeze_golden.py --develop-only`，
  连续两遍冻结必须逐字节一致。
- 显影主链：三张 48×64 图（色相渐变/硬边/带噪）× 参数组合，**47 个 case**
  （`acceptance/oracle/golden/develop.json::cases`），逐像素比对，容差
  `tests/suite/develop_golden.rs::TOL = 2/255`（纯逐点阶段 1e-3）；哪些 case 参与由
  `develop.rs::STAGES_READY` 决定。
- 其余金标：deflicker（1e-4）、align、crop、cube（.cube 文本逐字节）等，
  见 `tests/suite/` 各 `*_golden.rs`。
- 分通道去闪的 `chan_ev` 在金标里按「曝光吃均值 + 残差补色差」拆开喂，对上即证明
  拆分无损（`develop_golden.rs::run_case` 注释）。

### 10.3 自证式判据与变异测试

- 拟合判据集中在 `tests/suite/fit_sliders.rs`、`fit_denoise.rs`、`fit_sharpen.rs`、
  `fit_sharpen_protect.rs` 与 `dehaze.rs` 的 fit 模块；扫参表用
  `cargo test -p aevum-core --lib dehaze_sweep -- --ignored --nocapture` 出。
- ICC 用 littleCMS 读回核（`AEVUM_ICC_DUMP` + `acceptance/oracle/check_icc.py`）。
- 真实样本：`tests/suite/raw_real_sample.rs`（尺寸两路互证 / CFA 结构 / 能力边界回退 /
  真实内容与确定性）。
- 变异测试实践：改一个常量/退一条逻辑必须有判据接住——已验证的例子如 B5 的两个变异
  （CFA 映射、IFD 选择）都报红；阈值类常量（A5–A9）每个数都有独立判据，改任何一个
  都有对应的红。
- 规模口径：三个 crate 的集成测试合为 3 个可执行文件、判据 892 条一条不少
  （台账 C1）。
