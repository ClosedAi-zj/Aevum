# 时间合成 · 设计笔记（2026-11-02）

## 1. 它要解决什么

风光延时的两种经典合成，PS 里都能做，但都要靠手：

- **天地合成**：天用日落后那张（云有色、地面已黑），地用最亮那张（地面还有细节）。
  PS 的做法是叠两层 + 刷蒙版 + 接缝处拉曲线。换一组素材，蒙版全部重刷。
- **时间切片**：把画面横切成若干带，每一带取序列里不同时刻的一帧，云因此被拉成
  一段连续的时间。PS 的做法是复制 N 层、逐层方形蒙版、再逐条接缝修。

两者的共同成本不是算法，是**每次都要重来**。AEVUM 把这件事拆成三个可以分别验证的
步骤：选帧 → 羽化 → 曝光匹配。参数化之后，换素材只是换帧号。

## 2. 逆向证据（PS 的堆栈到底怎么做的）

来源：Photoshop 2025（`D:\app\ps\Adobe Photoshop 2025\Photoshop.exe`，
201,268,720 字节，sha256 `f0fd8c6c20089511…`）。三条独立可核路径：

### 2.1 随包脚本（E2）

`Presets/Scripts/Statistics.jsx`（184 行）把 11 个统计模式映射到 ClassID：

| 界面模式 | ClassID | statistics.8ba 导出 |
|---|---|---|
| 平均值 | `avrg` | `MEAN_ENTRY` |
| 求和 | `summ` | `SUM_ENTRY` |
| 最小值 | `minn` | `MIN_ENTRY` |
| 最大值 | `maxx` | `MAX_ENTRY` |
| 中间值 | `medn` | `MEDIAN_ENTRY` |
| 方差 | `vari` | `VAR_ENTRY` |
| 标准差 | `stdv` | `STDDEV_ENTRY` |
| 偏度 | `skew` | `SKEW_ENTRY` |
| 峰度 | `kurt` | `KURT_ENTRY` |
| 范围 | `rang` | `RANGE_ENTRY` |
| 熵 | `entr` | `ENTROPY_ENTRY` |

脚本层用 `applyImageStackPluginRenderer` + 类 `imageStackPlugin`，堆图层由
`CreateImageStack.jsx` 完成。**这说明 PS 的「统计」不是图层混合模式，而是一个
独立插件按帧读像素、逐像素算统计量**——这一点决定了它的结果和「把图层设成 50%
不透明度」不是一回事。

### 2.2 插件导出表 + 反编译（E1）

`Required/Plug-ins/Image Stacks/statistics.8ba`（PE32+ DLL，102,384 字节）导出
11 个具名入口，Ghidra 反编译确认地址：

`MEAN@d1f0` `SUM@db40` `MIN@d520` `MAX@d070` `MEDIAN@d3a0` `VAR@dcc0`
`STDDEV@d9b0` `SKEW@d820` `KURT@cee0` `RANGE@d6a0` `ENTROPY@cd50`

每个入口的结构一致：`NewHandle(0x38)` 分配 56 字节上下文 → `switch(mode)` 分发。
**同一个 mode 字在不同入口含义不同**（`MEDIAN_ENTRY` 的 case 1 → `FUN_18000ae00`，
`MEAN_ENTRY` 的 case 1 → `FUN_18000a900`）⇒ 分发的是**位深/通道格式**
（8 / 16 / 32 位），不是统计量。也就是说每个导出只负责一种统计量，内部再按位深
分三条代码路径。

分块策略是写死的，可以照抄：

- 宽 `w` 夹在 `[1, 2_000_000]`；
- 高 `h = (int)sqrt(buffer_bytes / (width * 2 + 2))`，再夹在 `[16, 1024]`；
- 深度 8 → 0x10 → 0x20 三档，决定每像素字节数。

导入表里**只有宿主 API 与 CRT 内存函数**：`PLUGIN.dll` 的 `NewHandle` /
`HostAllocateBuffer` / `HostLockBuffer` / `HostFreeBuffer` / `BlockMove` /
`WarnHostBufferProcsAvailable` / `WarnHostAdvanceState`，加 `MSVCP140` /
`VCRUNTIME140` 的 `memcpy` / `memmove` / `memset`。**没有 `qsort`，没有数学库**
⇒ 中值一定是内联在像素循环里的（小数组选择/插入，而不是排序整个栈）。

留白（没查到、不编）：中值的内层到底是直方图还是选择算法、32 位文档是否整条走线性、
SIMD 展开方式。这三项不影响我们的实现选择。

### 2.3 本地逆向库（E1/E2）

`E:/code/ps-lr/docs/adobe-algorithm-atlas.md` §33（多曝光合并）给了 ACR 的合并链：

1. `ExposureNormalize`——先按每帧曝光增益归一；
2. `ComputeDeghostMap`——**低分辨率**上算鲁棒中值当「无鬼影参考」；
3. `SoftenDeghostEdges`——对去鬼影标签做边缘软化；
4. `PipeNearestResampleDeghostLabels`——**最近邻**上采样回全分辨率；
5. `BlendWithBlurredMask` / `weighted_add`——按权重混合。

第 2 步和第 4 步是关键：掩膜在全分辨率上算太贵且噪声大，低分辨率算完再最近邻放大，
接缝反而更稳。**我们这一版没做去鬼影**（见 §8），但变量命名按这条链预留。

## 3. 图层混合公式与 gamma 域陷阱

PS 的图层混合（含不透明度）是：

```
Co = (1 − αb)·Cs + αb·[(1 − αs)·Cb + αs·B(Cb, Cs)]
```

其中 `B` 是混合函数：Lighten = `max`、Darken = `min`、Screen = `1 − (1−a)(1−b)`、
Multiply = `a·b`。αs = 1、αb = 1 时退化成纯 `B(Cb, Cs)`。

**陷阱在「平均」**。若在 gamma 域逐像素取平均，因为 `γ` 是凹函数，Jensen 不等式给出

```
mean(γ(x)) < γ(mean(x))
```

即：结果系统性偏暗，暗部与星点最先糊掉。这正是「在 PS 里怎么调都差一口气」的主要
来源之一。所以 `stack.rs` 与 `timeblend.rs` **全部在线性 f32 上做**，显影链在合成之后
——绝不在每帧先调色，那等于把两条非线性曲线叠起来，接缝再也对不齐。

## 4. 我们的实现

### 4.1 三件事

| 步骤 | 做什么 | 参数 |
|---|---|---|
| 选帧 | `Layout::SkyGround` 按地平线分天地（上取末帧、下取首帧）；`Layout::Bands` 按带数把整幅从早到晚铺满 | `layout` `bands` `horizon` |
| 羽化 | 带边界用 smoothstep `3t²−2t³`，交界处两侧权重**恒和为 1** | `feather`（占画面高度比例，默认 0.04） |
| 曝光匹配 | 按全帧亮度中位数把来源帧对齐到参考帧再混，增益钳 ±2 EV | `match_exposure`（默认开） |

### 4.2 两条不变量

1. **权重和恒为 1**：`s(t) + s(1−t) = 1`（smoothstep 的对称性）。相接不会整体变亮
   或变暗。这是 `band_weights_always_sum_to_one_across_a_boundary` 逐行扫出来的。
2. **外沿权重钉 1**：首带的上沿、末带的下沿是**画面边**而不是接缝，那里权重必须
   恒为 1。这一条是判据当场抓出来的真 bug：第一版首带顶端只拿到 0.84 的权重、
   没有第二个带来补，画面最上一行会偏暗（详见提交 `f9efe60`）。

### 4.3 曝光匹配的细节

- 亮度中位数：线性域、RGB 取平均、**最多抽 4096 个样本**排序（一张 45MP 的帧排
  4500 万个数没意义）。
- 参考帧取 `frames[len/2]`（中间那一帧）：取首帧会偏亮、取末帧会偏暗，中间最稳。
- 增益 `clamp(reference / source, 0.25, 4.0)` = ±2 EV；来源帧近零或非有限时
  直接放弃匹配（宁可不匹配，也不要把它放大成一片噪点）。

## 5. 四条关键决定

1. **线性域**，理由见 §3。
2. **smoothstep 而不是线性渐变**：线性渐变在拐点处一阶不连续，屏幕上是一条硬边；
   smoothstep 两端导数为 0，肉眼看不到起止。代价是过渡带实际宽了一倍，
   所以 `feather` 取的是**半宽**。
3. **MAD 而不是标准差**（这条同时用于筛选台）：日落渐变里标准差把「光在变」读成
   「离散大」；少量真废片又把标准差进一步拉宽，两个效应互相抵消。MAD 只看中间
   一半，区间才收得回来。
4. **不做逐帧调色**：一旦每帧先过曲线，两条非线性叠加后接缝无法对齐。合成必须
   在「裸线性像素」上完成。

## 7. 参数默认值与它们的道理

| 参数 | 默认 | 理由 |
|---|---|---|
| `layout` | `sky-ground` | 用得最多的场景；带切片是进阶玩法 |
| `bands` | 8 | 一屏八带，每条肉眼能分辨「这是另一个时刻」；再多就成条纹 |
| `feather` | 0.04 | 1000 px 高约 40 px 过渡，够藏住接缝又不会糊掉云的结构 |
| `horizon` | 0.5 | 多数构图地平线在中线附近；界面可拖 |
| `match_exposure` | 开 | 不同时刻的帧本来就差档位，不匹配必然一道台阶 |
| `MAX_FRAMES` | 32 | 带数上限 32；再多每条带只剩几行像素 |

## 8. 已知缺口（下一轮）

1. **去鬼影**：现在带边界上「同一物体在两个时刻位置不同」（云、树、车流）会出现
   拖影。ACR 的做法（低分辨率鲁棒中值 → 软化 → 最近邻上采样 → 混合）已在 §2.3
   记下，`Spec` 里预留了开关位置但未实现。
2. **天空自动分割**：现在靠一条水平线。真正的做法是按梯度/颜色做软分割，
   `mask.rs` 有现成的线性/径向/画笔组件可以复用。
3. **全分辨率预览**：现在必须先合一张（写盘）才能看结果。理想是面板上直接半分辨率
   预览，改动参数即时反映。
4. **筛选台的「剔除成子序列」**：现在只能标排除（旗标），没有「把保留帧另存成一个
   新序列目录」。这条涉及批量写与路径安全，单独一轮做。
